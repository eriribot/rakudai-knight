## 接入黑白 ADV 轮盘终端的位置

目标目录：`scripts/黑白ADV轮盘终端`。本次仍是独立预览，正式终端源码未修改。

1. 在 `terminal-app.js` 的 `renderSchedule()` / `#schedule-body` 中加入“校内选拔 / 七星剑斗祭”视图切换，沿用 `openApp('schedule')` 入口和现有刷新路由。
2. 终端现有 `stat_data.场景.选拔赛` 对应校内积分选拔：20轮、6名额、288号池。全国单败淘汰、一对四和资格判定应使用独立全国赛数据，不能套入现有积分算法。
3. 本地原著赛果是预览样例。实际游玩要读取当前剧情已发生的赛事状态；玩家参赛或改变赛果时，以游玩记录更新签表，不锁死原著胜者，也不提前显示后续结果。
4. 复用终端 `renderKnightAvatar()` 与既有头像清单；界面外壳沿用 `terminal-theme.css` 的黑白变量，六边形彩色赛事屏放在内容区域。
5. 正式迁入时按终端组件前缀隔离选择器，并交给 `bundle.mjs` 内联构建；不用让酒馆读取本地 `assets/` 路径。

## 2026-10-13：沿用现有 MVU 的预览接线

- `系统.主角模式`、`玩家.姓名/所属/固有灵装/登记等级` → 当前玩家档案。
- 与现有终端同源的 `deriveTournament(stat)` → `view.playerId`、名册、实际比赛、积分与完整性。不能把 `eligible` 当作已获资格名单；只有完整赛季结束、无名额边界同分、当前快照已保存时才由完整榜单确认本预览的代表名单。
- `场景.选拔赛` 仍为原来的 20 轮校内积分赛，不放入全国赛单败对局。常规 T02 背景投影不等于完整全校账本；真实游玩的代表确认与全国赛字段仍待正式设计。
- 玩家头像仍属于当前聊天本机显示配置，不增加 MVU 头像字段。以后可将现有头像服务解析的 `src` 作为 `avatarUrl` 传入。
- 当前离线入口：`RK_MATCH_PREVIEW.setSnapshot(snapshot, {avatarUrl})`。输入变化会重新读取角色并清空旧的全国赛演示；它是预览的只读接口，不是酒馆事件监听或写回接口。
- “完整账本”是明确标注虚构的 288 人旧账本样本，无结束日期，因而正式引擎只读取完整历史、不追加背景投影。不得把这份基线用于真实存档。
- UI 保留 A—D 分区晋级总览；点对局进入胜者大屏，玩家行动通过正文草稿入口。B区原著一对四放在原著回放，本局不默认触发或默认取胜。

本轮离线验证：角色身份/完整账本/同分/等待 MVU/他校/一辉唯一性；32席唯一、代表去重、赛果传播及改判清理；桌面与420像素窄屏交互。尚未迁入真实酒馆终端。
