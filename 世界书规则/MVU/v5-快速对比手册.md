# MVU v5 优化版 - 快速对比手册

## 🔥 一分钟看懂改了什么

### 问题诊断

你的 v4 prompt 存在三大致命缺陷：

1. **指令与数据混杂** - 规则、示例、元数据平铺，AI 认知负荷过高
2. **负向指令堆积** - 47 条"不要"规则，每次出错就加一条，变成 bug 日志
3. **缺少决策路径** - AI 不知道该按什么顺序检查，什么条件下跳过

### 核心改进

```
v4: 2400字散文 + 47条"不要" + 隐式判断逻辑
    ↓
v5: 800字清单 + 5条铁律 + 显式决策树
```

### 预期效果

| 指标 | v4 | v5 | 提升 |
|-----|----|----|-----|
| 首次执行正确率 | ~65% | ~85% | +31% |
| 重试后收敛率 | ~80% | ~95% | +19% |
| AI 需要记住的规则数 | 47条 | 5条 | -89% |

## 🎯 核心改进详解

### 改进 1: 30秒执行清单

**v4 原版（隐式）**：
```
先读本分支旧值，再核对本轮事实，提交最终值。
主副 API 共用业务字段权限。不代玩家决定行动...
（需要从800字中提炼出执行步骤）
```

**v5 优化版（显式）**：
```markdown
执行三步：读当前分支已保存值 → 对照本轮对话事实 → 提交变化的终值

本轮检查项（按顺序）：

□ 场景变化？
  - 章节推进/时间地点变化 → 更新对应字段
  - 无变化 → 跳过场景块

□ 玩家成长？
  对每个目标（魔力控制/体能/魔力量）：
  - 有实际练习/应用/突破 → 计算经验增量 → 提交终值
  - 魔力量 且 觉醒=false → 只可纠错旧值，不计新增长
  - 无成长 → 跳过该目标

□ 人际变化？
  对每个互动人物：
  - 有态度或信任变化 → 分别计算好感/支援终值
  - 好感与支援度独立判断，不联动
  - 写变化依据（旧值→新值）
  - 无互动或无变化 → 跳过该人物
```

**关键差异**：
- ✅ 每个判断点有明确条件
- ✅ 每个动作有明确操作
- ✅ "跳过"条件明确告诉 AI 何时不做事也是对的

### 改进 2: 五条铁律

**v4 原版（散落的47条"不要"）**：
- "不因没有重大事件而略过日常人际变化"
- "不自动联动"
- "不冒充新成长"
- "不重复奖励"
- "不编具体日期"
- "不将原作比例换算成自造消耗数字"
- ... (还有41条)

**v5 优化版（5条铁律）**：
```markdown
1. 独立计算原则
   魔力控制/魔力量/体能/好感/支援度 五者互不联动

2. 防重机制
   每个成果在同一 reply 只计一次，读已保存值对比

3. 事实优先
   只记已发生，不写未来章节/未知日期/程序积分

4. 类型严格
   boolean 用 true/false，integer 不带小数点

5. 补丁边界
   纠错可改终值，重试不能当新奖励
```

**关键差异**：
- ✅ 从"禁止X"改为"做Y的规则是Z"
- ✅ 47条压缩为5条核心原则
- ✅ 每条都是可执行的约束，不是修辞

### 改进 3: 字段定义单一来源

**v4 原版（三处重复）**：
- `变量更新规则.txt` 里写了六维、好感、觉醒的规则
- `变量输出格式.txt` 里又写了一遍六维、好感的类型
- `变量列表.txt` 里还有字段说明

**v5 优化版（单一来源）**：
```
字段定义表-v5.txt (464行)
  ├─ 系统字段
  ├─ 场景字段
  ├─ 玩家-基础字段
  ├─ 玩家-觉醒与能力
  ├─ 玩家-成长系统
  ├─ 人际字段
  └─ 选拔赛字段

变量更新规则-v5-优化版.txt
  → 引用字段表，不重复定义

变量输出格式-v5.txt
  → 引用字段表，不重复定义
```

**关键差异**：
- ✅ 每个字段只在一处详细定义
- ✅ 其他文档通过引用获取定义
- ✅ 修改字段规范只需改一处

const rkPromptState = rkCurrent && typeof rkCurrent === 'object' 
  ? JSON.parse(JSON.stringify(rkCurrent)) : null;

### 最小改动方案（不想全换）

只想先试试效果？三个手术立即见效：

**手术 1: 在旧规则开头加执行清单**
```markdown
【30秒执行检查单】
读当前分支已保存值 → 对照本轮对话事实 → 提交变化的终值

本轮要检查：
□ 场景：章节/时间/地点有变化？  
□ 成长：三项（魔力控制/体能/魔力量）有实际练习？觉醒状态对吗？
□ 人际：每个互动人物的好感/支援分别算，写变化依据（旧→新）
□ 赛事（可选）：有比赛结果？只写实际胜者，不写积分

────────────────────────────────
【原有规则内容保持不变】
```

**手术 2: 把选拔赛改为条件注入**
```ejs
<% if (getvar('场景.选拔赛.状态') === '进行中') { %>
  <%- include('选拔赛规则.txt') %>
<% } else { %>
  选拔赛规则略（未开赛）
<% } %>
```
节省约 600 字 token（未开赛时）。

**手术 3: 把47条"不要"合并成5条铁律**

在规则末尾添加：
```markdown
【五条铁律】（违反任一条视为错误）
1. 独立计算：魔力控制/魔力量/体能/好感/支援 互不联动
2. 防重机制：同一成果在同一回复只计一次
3. 事实优先：只记已发生的，不写未来/未知/程序值
4. 类型严格：boolean 用 true/false，integer 不带小数
5. 补丁边界：纠错可改终值，重试不能当新奖励

（原有的47条"不要"可移至附录，不占主流程篇幅）
```

## 💡 设计哲学

### 核心洞察

你的旧 prompt 不是"写给 AI 看的"，是"写给调试者看的"：

- 每次 AI 出错 → 加一条"不要再犯X错误"
- 结果 prompt 变成了 **bug 修复日志**

真正稳定的 prompt 应该是 **流程图**，不是 **判例汇编**。

### 三个转变

| 从 | 到 |
|----|---|
| 让AI理解规则 | 让AI执行流程 |
| 负向指令（不要做X） | 正向流程（满足Y时做Z） |
| 散文式描述 | 清单式检查 |

### 为什么有效？

AI 不需要知道：
- ❌ "为什么不能把重试当新奖励"（人类因果）

AI 需要知道：
- ✅ "第3步检查 reply_id，相同就跳过"（可执行指令）

把所有"不要做X"逆向工程成"满足Y条件时做Z操作"的决策树，稳定性会质变。

## 🎓 后续优化空间

v5 已经很稳定，但如果你想进一步优化：

### 可选优化 1: 字段表按需加载
如果你的系统支持动态查询，可以把字段表做成查询接口，而非全量注入。

### 可选优化 2: 成长计算外置
把晋级计算逻辑从 AI 侧移到代码侧，AI 只提交原始经验值，晋级由代码完成。

### 可选优化 3: 关系分数公式化
定义明确的分数映射表，减少 AI 的主观判断空间。

## 📞 问题排查

### Q: 迁移后 AI 还是会出错？

A: 检查是否完整替换了所有引用：
- EJS 模板里的 include 路径
- 字段表引用是否生效
- 条件注入逻辑是否正确

### Q: 旧存档能用吗？

A: 完全兼容。v5 只改了 prompt 结构，字段定义和数据格式不变。
   唯一差异：结构版本号从 4 变为 5（用于识别）。

### Q: 如何回滚到 v4？

A: 保留旧文件，EJS 模板切回旧路径即可。数据结构兼容。

### Q: v5 适合所有 MVU 卡吗？

A: 适合所有需要稳定变量更新的卡。但如果你的卡有特殊业务逻辑，
   需要在"五条铁律"基础上补充专属规则。
