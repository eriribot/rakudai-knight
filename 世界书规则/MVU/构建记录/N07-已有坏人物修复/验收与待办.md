# N07 · 已有坏人物修复

交付边界为组件更新：只发布 `落第骑士-小手机-v1.3.23.json`，复用原生 N04、开局 N06、MVU02 字段约束。没有导入新脚本到用户酒馆，没有调用模型，没有写用户聊天变量或历史楼层。源开局页中的共享控制器保持同步，但本次新增只读验证接口仅被小手机使用，已安装 N06 开局仍可沿用。

## 已确认原因

- 用户贴出的完整人物对象与错误通知中的简写对象不同。后者的 `支援`、`印象` 是未知键，还缺少 `态度印象`、`羁绊阶段`、`变化依据`；完整字段类型夹具通过当前 schema，不能把该通知归结为标签没收尾。
- 原生模式可以保存不完整的人物。之后启用 Zod 桥接时，每个补丁都检查整个状态，逐字段修复会互相阻塞；两条坏人物逐人修也会阻塞。旧副校正把完整既有人物拆成字段补丁，因此同样失败。
- 剧情面板读取会完整验证存档。坏人物导致按钮暂不可用，旧 UI 却统一显示“等待 MVU”，并把可选约束提示写成了必需。
- Zod 重排对象键与保存合并保留旧键序并存，原来的直接 JSON 字符串比较可能造成内容相同却报回读失败。

## 改动

- 副校正在内存合并修改后，优先一次提交完整 `/人际`；保留未改人物及省略资料，错误字段仅按显式 remove 删除。
- 明确副模型的人物字段契约；缺失的羁绊阶段可补，按有效最终支援度使用现有公式派生，不猜分数或经历。
- 写入前复用完整档案校验。仍不合法的候选不写入，显示错误路径；不会以部分变化掩盖结构修复失败。
- 保存及并发比较忽略对象键序，保持数组顺序和所有真实业务值检查。
- 面板区分加载、真正等待、数据非法和服务不可用。手动切章与主 API 直接提交相邻目标卷章不需要可选约束；只提交“本章已结束”时的代码自动推进仍由可选约束提供。
