## 仍未修改的诊断结论

- 主保存确认依赖 COMMAND_PARSED、VARIABLE_UPDATE_ENDED、后续 CHARACTER_MESSAGE_RENDERED；渲染先到时无法满足当前顺序条件。离线可复现变量已存但等待至 180 秒的情况。重试只延长等待，不恢复漏掉的事件。
- 不开约束仍受原生 JSON Patch 规则影响。固定版本 MVU 更新函数加当前 N03 的内存模拟中：缺父对象、对不存在字段 replace 均失败；有效操作加无效路径可部分成功；操作缺 path 或 JSONPatch 未闭合可导致整块未提取。
- 原生解析器可提取部分 JSON5 / 缺 UpdateVariable 外壳的内容，本卡严格 replyMvuBlock 会拒绝。是否发生于用户现场，仍需对应版本和实际回复证据。
- 副 API 已有广泛业务写权限，但入口要求主回复带有效补丁且当前槽状态完整，使其无法接手一部分原本应修复的坏结果。下一步应解耦“真实回复身份”和“原补丁合法性”，设计主保存与副 API 修复的写入交接，避免晚到的主保存覆盖修复。
- 主保存后串行执行副 API，副请求非流式；当前 120 秒超时、最多 3 次尝试及间隔，在失败路径可累计约 367 秒。该数值不是正常请求耗时测量。
