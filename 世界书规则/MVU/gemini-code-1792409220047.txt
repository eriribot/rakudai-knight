【变量更新规则】
先读本分支旧值，再核对本轮事实，提交最终值。本局剧情、玩家设定与已保存变量优先于原著默认走向和模型记忆；不强制还原胜负、关系、死亡、觉醒时间或能力。不代玩家决定行动、内心、台词；计划和预告不记成已完成。
主副 API 共用业务字段权限。主回复每轮自行检查场景、成长、遇见或互动人物的好感与支援、联系资料及赛事事实；实际变化当轮提交，不等副 API 或玩家提醒。不因没有重大事件、没有自身成长而略过日常人际变化。补漏与重试均使用当前聊天、楼层和回复页，只补漏或纠错，同一成果、重试和副校正不再次相加。

【保存与字段】
已建档不重建；待建档补丁为 []，由开局页完成建档。v2/v3 先经终端迁移；一辉模式不另建同名 NPC。固定字段及数据类型见输出格式。
代码维护 /系统、/玩家/性别、/玩家/综合初评、成长版本与收据、/人际/<姓名>/名册隐藏及框架元数据。旧成长申请与收据只读留档；模型更新业务事实，不覆盖父对象重置它们。/系统/已删除人物 随分支保存，不从旧正文重建其中人物。
玩家资料、能力、六维、正式登记等级、成长经验最终值、人际资料及分数均可按已确认事实修正；不另需终端审批。通常写具体叶字段；合并已有对象时保留未提到的资料。能力、事件、人际中的错误条目可以删除，离场或暂时失效不等于删除。

【能力、评级与觉醒】
伐刀能力包含能力系别、能力本质、共通限制、招式；剑术、体术、分析、生活技艺归其他能力。按本局实际学习、应用、改良结果更新，描述自由，不凭招式名称或原著未来资料授予掌握。
六维实际档位按事实保存；永久成长与评级纠错可改六维，临时强化、疲劳或受伤写在描述中。正式登记/重评发生时可改登记等级，开局综合初评仍保留历史。无统一 HP/MP/AP/SP，不将原作比例换算成自造消耗数字。
唯一觉醒开关为 /玩家/魔人觉醒（布尔值），缺字段按 false；本局明确觉醒才设 true，误记可按事实纠正。true 后不反复注入觉醒旧事，不以旧成长境界、卷号、字数或能力名替代布尔开关；觉醒本身不赠经验。

主副 API 直接提交 /玩家/成长/经验/<目标> 的非负整数终值及 /玩家/六维/<目标> 的最终档位，不新建成长申请。经验只记魔力控制、体能、魔力量三项，彼此独立。已有经验与六维可据已确认事实纠错，包括未觉醒时的魔力量旧值；纠错不冒充新成长，评级未知时不猜起点。

【剧情、事件与日程】
宿舍按钮维护 /场景/宿舍 布尔值，缺项按 false；true 表示终端正在显示宿舍背景。模型不得进入宿舍、自动改地点或覆盖该标记；玩家主动点击离开由代码设 false。
仅当本轮玩家指令为“休息”或“宿舍休息”，且旧 /场景/宿舍 为 true，才输出休息一晚及次日清晨的叙事，按上下文更新 /场景/时间（无明确日期不造日期，不保留原小时数），同时设 /场景/宿舍=false；保留地点和历史事件，终端恢复原背景。非宿舍时拒绝这两个休息指令，不推进时间、不提交休息补丁。
章节完成标识和剧情内容以当前绑定条目为准，不能用目录概要替代。未开始实际入章可改进行中；进行中已满足完成标识，可写已结束（或已完成，代码归一为已结束）交代码推进，或写注入目录的相邻节点及进行中。本轮最多前进一个节点，主副共用本轮进度；正文停在交接处，下一轮展开新章。未确认完成就保留，不因转场或战斗结束自动切章；手动向前切入使用终端。
完成事件归推进前章节，同事件补原键；只保存已发生结果，不写未来章节，不把不知情者列入。场景时间、地点、切入说明按实际情况更新，未知不编具体日期。日程只记本局已知安排，未知日期留空；实际开始/完成再改状态，完成另记事件。过期、缺席、未来原著安排不自动视为发生。取消或改期保留原条目和依据。

【人际与分数】
本局实际识别或明确认识的人物可建档；名单和传闻不等于见过。保留亲属、师生等背景关系，不因低分当陌生人。联系状态记录仅识别/已建立联系，首次双向言语或行动即建立联系；联系依据简记建立联系时的双方行动，后续日常互动不覆盖已有联系依据。已加联系方式独立，只在渠道成立时为 true，不以面对面交流代替。
按事实补性别、身份、登记等级、灵装、已知能力；不填世界书秘密或未来资料。普通新人物好感/支援从0计，已确认背景可按实际深度直接核定。旧数字续算，不归零套初见奖励；未知/旧null保留待核定，可在事实明确时修正。
好感表现对玩家态度变化，支援表现落实的支持、协作和信任，二者独立。正常友善回应可有普通好感+2—10；新生轻微好感、认可或防备缓和可参考中度+11—20；重大关系改变可参考重度+21—40。负向变化按实际影响核定，支援日常协作可参考+1—5、克服阻碍+6—10、重大协作+10—15。这些为叙事尺度参考，不是硬上限或审批分类。
有对应回应就及时改分，不能只改态度印象；仍羞恼、没有恋爱、没有重大事件不等于无好感。只有玩家单方示好不强加对方好感；闲聊或许诺不自动增加协作支援。变化依据用一句简短事实记本轮变化与旧值→最终值，不追加历史旧依据，不要求独立突破依据、固定关键词或换措辞。一次回复给每人每项一个合并终值；后续可纠错终值，不能将重放补丁作为新奖励。
羁绊由支援派生（0—79未建立、80—159 C、160—239 B、240—319 A、320 S）。恋爱阶段只对已确认女性且好感有效者派生（0—199路人、200—499在意、500—799暧昧、800—999交往、1000生死相随）。阶段是表现参考，不倒补未发生告白、婚约或亲密经历，不授予觉醒。

【破军选拔赛】
/场景/选拔赛 保存本局名册与比赛，本卡默认20轮、288人号池、6席。日期与背景结果由程序维护；只登记已知排期及实际赛果，玩家缺场保留待补。
名册和比赛沿用稳定ID；每轮每人至多一场，已安排或完成的对手组合不重复，取消不占对手和积分。同场纠错沿用原ID，由程序重算战绩积分。
本局胜负优先于原著和背景推演。退选或取消资格更新参赛状态；新人物仅在明确中途入赛时填入赛轮次。实际发生一辉拘押时可设/场景/选拔赛/一辉拘押=true，程序据此调整延赛。
选拔结束时按本局结果确认代表，并更新资格名册；具体字段与程序维护项见输出格式。

【七星剑斗祭代表资格】
各校统一用/场景/七星剑斗祭/资格名册。沿用资格或选拔ID，无ID玩家用player。明确选定、落选、取消或恢复时更新原记录；玩家确认与纠错有效，缺记录待确认。
战绩与资格独立；取得或恢复设已取得，失去设已取消，原因简记依据，原战绩保留。按已发生的正式决定更新，争议和预告保留待定。首次补齐缺少的父对象。

【七星剑斗祭赛程】
按本局通知登记比赛、分区和参赛者，支持多人对战。参考日历只供排期；胜者和晋级按实际结果记录，保留玩家行动选择。

本局改期更新开始日期、结束日期，状态随实际开幕或结束更新；未知时间留空。比赛与晋级记录使用资格名册ID，新增选手先补资格记录。原著签表与回放不写作本局结果。
