# v4 兼容修复 N03、终值成长与 OC 头像

主 API 直接更新 `/玩家/成长/经验/<目标>` 与 `/玩家/六维/<目标>` 的最终值，新成果不再经过成长申请。模型根据本轮事实、原经验和当前评级计算晋级及余量；需要程序核对准确门槛时，可另开当前 v4 字段约束。副 API 只校正漏项和错误终值，不重新发放同一成果。

N03 补缺失成长、经验容器及经验缺轴的 `0`；原生模式保留 N02 对历史申请父对象的兼容，当前 `final-values-v1` 约束模式不新建申请。旧申请、旧收据和未知字段留在存档，不因升级删除或自动兑现。安装与重载不重新初始化已有聊天，也不重放旧失败补丁。

## 模式与责任

| 当前 v4 字段约束状态 | N03 | 成长处理 |
| --- | --- | --- |
| 关闭 | 开启 | 补缺失结构并使用原生可写 schema；主 API 计算并提交经验、评级与余量，按模型终值保存。 |
| 开启且完整注册 | 开启 | 主 API 仍写终值，约束按准确门槛核对成长、连续晋级与余量；旧申请留档不兑现。 |
| 正在加载或注册失败 | 开启 | N03 仍只补缺项，不切换原生 schema 绕过约束；先恢复约束或明确关闭它。 |

当前约束发布 `growthProtocol: 'final-values-v1'`，保留 G04 等兼容能力标记。只有脚本名称或开关，不能证明新协议已注册。旧 G04 约束与旧独立成长均须按当前清单升级或关闭。

小手机提供界面、补漏与回读。普通主回复 MVU 保存独立于副 API；关闭副 API 不影响主回复变量更新。N03 独立脚本可在小手机关闭时修复真实 MVU 更新的缺失父对象。

## 自动修复的范围

N03 只处理根对象包含 `系统`、`场景`、`玩家`、`人际` 且 `系统.结构版本` 为数字 `4` 的本卡状态，不迁移 v2/v3、英文档案或损坏的玩家父对象。

- 缺 `玩家.成长`：补可写成长容器。
- 缺 `成长.经验`：补经验对象；经验对象中缺魔力控制、体能、魔力量时，只对缺轴补 `0`。
- 缺 `成长.申请`：仅原生模式沿用 N02 的旧补丁兼容，补空对象；当前 `final-values-v1` 约束模式不新建申请。新规则不提交或兑现申请。
- 已有经验、申请、收据、未知字段：保持原值，不清空、不改名。
- 已有 `null`、数组、字符串等坏类型：结构修复保留原值，不用空模板覆盖；明确纠错仍交 MVU 按补丁执行。

补零只建立缺失的进度字段，不推断六维、觉醒或曾经获得的经验。安装与重载本身不写聊天；下一次真实 MVU 解析才处理当前传入的状态副本。不批量改写历史楼层，也不借其他 swipe 的数据填空。

## 终值成长与旧账

普通状态开放魔力控制和体能成长；`玩家.魔人觉醒: true` 后开放魔力量，觉醒本身不赠经验或等级。主 API 以当前评级的档内经验为起点，按已完成的实际成果增加进度。达到门槛时提交晋级后的六维评级和剩余经验，登记等级仍只记录实际登记或重评。

档位门槛为 F100、F+100、E150、E+150、D250、D+250、C400、C+400、B600、B+900、A1200、A+1600；可连续晋级并保留余量，S 为顶档。经验使用非负整数，终值不按旧申请的 9999 上限截断，S 档保留余额。不能凭跳章、回忆或重试重复加同一成果。当前规则与输出格式负责具体计算约定，可选约束核对准确门槛。

旧申请不再自动兑换经验，旧历史与收据仍保留；不能把“申请已经保存”当成“经验已经增加”。主、副 API 的请求副本省略这些旧账，不删除原 `stat_data`。旧漏项需要有依据地校正当前经验与六维终值，不将旧申请重新当作奖励队列。

## 玩家怎样修补旧漏项

N03 能防止后续缺父路径错误，旧失败操作不会因安装而自动追回。小手机仅操作**最新助手楼层的活动回复页**；滚动查看或编辑旧正文，不会把手机切到该历史楼层。

如果漏项属于当前最新助手回复：

1. 确认聊天、楼层与活动回复页，等当前回复的唯一完整 MVU 标签和已建档 v4 变量可读。
2. 打开小手机 → 设置 →“副 API · MVU 校正”。在“补充说明”粘贴原失败操作作为事实依据，注明未落实的成果、原经验、当前评级及应修正的终值；旧申请只作依据，不要求重新兑现。截图中的 `&quot;` 应还原为可读引号。
3. 保存配置后点击“手动校正并预览”。核对预览确实包含该漏项对应的经验／六维终值；返回 `[]`、无需修改或仅改其他字段，都不算修补成功。
4. 核对后点击“应用预览补丁”，等待“已保存，当前回复页回读一致”。再检查实际经验与评级，重载后确认仍在同一回复页保存。

如果漏项已经位于更早楼层，不用当前手机冒充对历史楼层重算。保留原补丁与当前变量，逐项核对哪些成果未落实，再修正有依据的当前终值；多楼历史无法凭一条“没问题”提示宣布追回。不要用空初始化模板覆盖旧存档。

切聊天、切 swipe、生成新楼层、修改 MVU 标签或发生并发变量变化后，旧候选失效，应重新读取状态。预览成功、变量展示标题或副模型的文字判断均不能替代实际保存回读。
