## 安装顺序

1. 保留原角色卡与需要继续使用的聊天备份。当前已有[实机导出的原卡备份](../../output/chapter-v4/runtime-original-card.json)，它是角色卡备份，不包含完整聊天。
2. 停用旧综合注入器 v2.0.0、旧 MVU v3 约束和旧终端 v1.3.5。检查全局与角色局部脚本，**每一种脚本只启用一个版本**。
3. 更新世界书与开局页面，再装入 v4 约束、终端 v1.3.6、章节注入器 v3.0.0。保留并启用 MVU 扩展；真正的 EJS 模板交给 ST-Prompt-Template 扩展处理，并启用其总开关。
4. **重新加载整个酒馆页面。** 旧脚本可能留下事件监听器，单独关掉开关不能作为清理完成的依据。完成重载后，再打开目标聊天与终端。
5. 查看终端剧情面板。旧 v3 存档应出现迁移差异；新 v4 存档应显示实际卷章。若提示服务未就绪或要求导入新版注入器，先检查版本、启用状态和重复脚本。

新开局仍从第一卷建档；多卷支持用于之后的顺序推进或明确向前切入。不要用重新初始化来处理现有聊天，也不要只在变量编辑器里把 `/场景/当前卷` 改成 2：卷章组合、阶段和历史事件需要一起符合状态规则。

## 旧存档：先看候选，再确认升级

终端只对**合法的 v3 第一卷存档**提供在线升级。打开面板和刷新状态都是读取操作，不会自动写入。

1. 展开“升级旧存档至 v4”，查看逐项差异。
2. 点击“下载迁移前备份”，保存当前 `stat_data`。这是当前状态树备份，不是完整聊天导出。
3. 确认候选后，点击“确认升级当前楼层”。提交后会重新读取并核对保存结果。

合法 v3 的迁移只把 `/系统/结构版本` 改为 4，并为已有事件添加 `卷号: 1`。玩家资料、人际字段、能力与历史事件内容保持原样；迁移和切章不会重新计算人物关系，也不会补出恋爱阶段。正常 MVU 结算仍使用原有关系计分规则。

提交只作用于**当前聊天中最新助手消息的活动回复页（swipe）**，并保留 MVU 外层数据。切换聊天、切换回复页、出现新楼层或状态被其他操作改动后，旧候选会失效，需要重新读取和核对。不会把另一回复页的数据借过来填空，也不会批量升级全部历史楼层。

未知版本、已损坏的 v3 数据或手改成其他卷的 v3 数据会被拒绝，不能用“强制确认”绕过。可用[离线迁移工具](../../scripts/migrate-worldbook-state.mjs)先审查单独的 `stat_data`：

```powershell
node scripts/migrate-worldbook-state.mjs --input "原始stat_data.json"
```

默认只输出差异与候选，不写文件、不改酒馆。需要保存候选时，增加 `--out "output/迁移候选.json"`；输出必须是项目内尚不存在的新文件。离线候选也不会自动写回聊天。

## 顺序推进与手动前跳

日常操作仍是“开始本章”→“结束本章”→“进入下一章”。按钮按当前阶段开放，卷内下一章沿用本局的时间和地点。

到达**目录中这一卷的最后一个节点**并结束后，面板显示“进入下一卷”。点击后填写目标时间、目标地点和切入说明，再点击表单里的“确认进入下一卷”。目标章以“未开始”保存，核对场景后再点“开始本章”。第 19 卷末不再开放后续卷。

章节按原作目录排列，不是按“序章、第一章……终章”固定拼接。例如第六卷以间章开始，第十六卷包含位于前面的“终章Ⅱ”；这些名称和顺序由共享目录决定。

需要跳过内容时，展开“手动向前切入”：

1. 选择比当前位置更靠后的目标卷和章。
2. 填写目标时间、地点与切入说明，核对表单中的起点和终点。
3. 点击“确认向前切入”，再开始目标章。

手动入口只允许严格向前，同一节点和回跳不能提交。它保留已有事件和人物状态，不自动补写跳过章节的战果、关系、能力或奖励。回看过去可使用已有聊天分支或回复页。

## 章节注入与预览

展开“章节注入与预览”，可以切换“启用章节注入”、查看最近一次注入目标与来源，以及点击“刷新注入预览”读取当前候选文本。预览不会调用模型，也不会推进卷章。

预览描述当前状态准备注入的内容；“最近一次注入”记录通过发送前复核的剧情块，不能证明服务端已经收到或生成成功。两者在刚切章后可以不同。以面板显示的卷、章、阶段和消息来源共同核对，不要只看正文标题。

注入器关闭或无法取得合法状态时，会显示相应状态或原因，不再静默假定“第一卷·第一章”。如果提示“请导入并启用新版章节注入器（3.0.0）”，检查上面的同名 JSON 文件和页面重载步骤。

这版注入器负责剧情文本。世界书里的 EJS 条件由真实模板扩展执行，不能用旧综合器继续代替模板扩展。

酒馆助手的后台请求可能在提示词准备完成之后才发出开始通知。因此，提示词事件只准备一个自有块，发送参数事件再次核对来源和预算；后台开始、切换聊天、停止生成或复核失败会撤回候选。没有可靠归属的请求跳过。上下文计数采用带余量的保守估算，媒体或工具预算不明时跳过注入；原请求内容保留。故事神谕并发仍需要实机验收，不能把事件记录当成隔离已经成立的证明。
