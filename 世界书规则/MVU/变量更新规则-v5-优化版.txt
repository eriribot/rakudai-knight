【落第骑士 · 变量更新规则 v5 / 执行优化版】

═══════════════════════════════════════════════════
【30秒执行清单】—— 每次必读
═══════════════════════════════════════════════════

执行三步：读当前分支已保存值 → 对照本轮对话事实 → 提交变化的终值

本轮检查项（按顺序）：

□ 场景变化？
  - 章节推进/时间地点变化 → 更新对应字段
  - 无变化 → 跳过场景块

□ 玩家成长？
  对每个目标（魔力控制/体能/魔力量）：
  - 有实际练习/应用/突破 → 计算经验增量 → 提交终值
  - 魔力量 且 觉醒=false → 只可纠错旧值，不计新增长
  - 无成长 → 跳过该目标

□ 人际变化？
  对每个互动人物：
  - 有态度或信任变化 → 分别计算好感/支援终值
  - 好感与支援度独立判断，不联动
  - 写变化依据（旧值→新值）
  - 无互动或无变化 → 跳过该人物

□ 选拔赛事实？（仅赛季进行中）
  - 本轮有比赛安排/结果 → 更新 比赛/<ID>
  - 只写实际胜者，不写积分/排名/赛前胜场
  - 无赛事 → 跳过

重要：同一成果在同一回复只计一次。重试/副校正时读已保存值，只纠错，不重复加分。
无任何变化时提交空数组 []。

═══════════════════════════════════════════════════
【五条铁律】—— 违反任一条视为错误
═══════════════════════════════════════════════════

1. 独立计算原则
   魔力控制/魔力量/体能/好感/支援度 五者互不联动
   每个目标分别判断，分别提交

2. 防重机制
   - 每个成果在同一 reply 只计一次
   - 重试/副校正前先读已保存值
   - 已有相同成果 → 只纠错终值，不重复加分

3. 事实优先
   - 只记本轮已发生的事实
   - 不写未来章节/未知日期/程序积分
   - 历史回忆/跳章不补造训练

4. 类型严格
   - boolean: 用 true/false，不是字符串 "true"
   - integer: 不带小数点
   - string: 未知时用空字符串 ""，不编造内容
   - null 有特殊含义，不随意使用

5. 补丁边界
   - 纠错和补漏可改终值
   - 但重试不能当新奖励
   - 代码字段（系统/性别/综合初评/收据）不由 AI 覆盖

【核心字段规范】—— 详细定义见《字段定义表》
═══════════════════════════════════════════════════

### 觉醒开关

/玩家/魔人觉醒
  类型: boolean (true/false)
  含义: 本局是否已确认魔人觉醒
  更新时机: 本轮明确觉醒时设 true
  影响: 
    - true 后：魔力控制/体能/魔力量 均可获新成长
    - false 时：魔力控制/体能可成长，魔力量只可纠错旧值

### 成长系统

经验目标: 魔力控制、体能、魔力量（三者独立）

经验计算:
  - 直接提交终值（非负整数）
  - 经验是当前档位内的进度
  - 达到门槛自动晋级并扣除

晋级门槛:
  F→F+: 100  |  F+→E: 100  |  E→E+: 150  |  E+→D: 150
  D→D+: 250  |  D+→C: 250  |  C→C+: 400  |  C+→B: 400
  B→B+: 600  |  B+→A: 900  |  A→A+: 1200 |  A+→S: 1600
  S为顶档，保留余量

成长条件:
  - 需要实际练习/应用/改良/突破
  - 体能成长需身体实际参与，纯想象不算
  - 魔力量新成长需觉醒=true

### 人际系统

好感: 0-1000（态度变化）
  参考增量（非硬性分类）:
  - 普通友善回应: +2~10
  - 认可/防备缓和: +11~20
  - 重大关系改变: +21~40
  - 负向变化按实际影响核定

支援度: 0-320（落实的支持、协作、信任）
  参考增量:
  - 日常协作: +1~5
  - 克服阻碍: +6~10
  - 重大协作: +10~15

关键规则:
  - 好感与支援独立，分别判断
  - 有对应回应就及时改分，不能只改态度印象
  - 普通友善对话可有好感变化，不需要重大事件
  - 支援需落实行动，许诺不自动增加

═══════════════════════════════════════════════════
【场景与剧情】
═══════════════════════════════════════════════════

当前卷: 1-19（整数）
当前章: 使用注入目录的稳定键
阶段: 未开始/进行中/已结束

推进规则:
  - 按实际完成标识判断
  - 本轮最多前进一个节点
  - 主副 API 共用本轮进度
  - 未确认完成就保留进行中

时间/地点:
  - 按实际情况更新
  - 未知时保持空字符串或已有值
  - 不编造具体日期

═══════════════════════════════════════════════════
【选拔赛规则 T02】—— 仅赛季进行中时注入
═══════════════════════════════════════════════════

基本设定:
  - 默认20轮、288人号池、6名代表
  - 始终跟随当前主角模式
  - 每轮每人至多一场
  - 同一对手组合不重复

比赛记录:
  轮次: 1-20
  状态: 待定/已安排/已完成/已取消
  只登记已知通知与实际战果

AI 提交内容:
  ✓ 可以写: 实际比赛ID、对手ID、胜者ID、依据
  ✗ 禁止写: 积分、排名、初始战绩、甲赛前胜场、乙赛前胜场、程序来源

积分计算（程序自动）:
  - 胜者获得: 10 + 10 × 对手赛前胜场
  - 败者: 0
  - OC打赢正典人物以实际胜负为准

特殊字段:
  - 入赛轮次: 只能由终端人工纠错
  - 初始战绩: 只能由用户手动补录
  - 一辉拘押: boolean，只有实际发生时置 true

【操作规范】—— JSONPatch 提交指南
═══════════════════════════════════════════════════

路径规则:
  - 以 /玩家、/场景、/人际 开头
  - 不以 /stat_data 开头
  - 名称不含 /、~、__proto__、prototype、constructor

操作类型:
  - add: 添加缺失的条目/父对象
  - replace: 修改已存在的值
  - remove: 删除已确认错误的动态条目

提交方式:
  - 优先提交变化的子字段
  - 提交对象时保留未提到的数据
  - 提交终值，不是增量

类型约束:
  - String/null/{}/[]/number/boolean 含义不同
  - 按字段定义使用正确类型

空结果:
  - 独立检查每个区域后确认无变化
  - 提交 []

输出格式:
  <UpdateVariable>
  <Analysis>简明英文：检查项 + 变化或无变化原因</Analysis>
  <JSONPatch>[完整JSON数组，无围栏/标题/注释/省略]</JSONPatch>
  </UpdateVariable>

【常见错误预防】
═══════════════════════════════════════════════════

✗ 不要做:
  - 日常交流略过人际变化（普通对话可有+2~10好感）
  - 把重试当新奖励重复加分
  - 魔力控制/魔力量自动联动
  - 好感/支援自动联动
  - 闲聊增加协作支援
  - 编造未知日期
  - 写选拔赛积分/排名

✓ 应该做:
  - 先读已保存值再计算
  - 每个字段独立判断
  - 按事实提交终值
  - 未知信息留空或保持原值
  - 变化依据简记关键事实
