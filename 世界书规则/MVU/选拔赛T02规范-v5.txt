【落第骑士 · 选拔赛 T02 完整规范】

本文档仅在 /场景/选拔赛/状态 = "进行中" 时注入提示词。
未开赛或已结束时不占用 token。

═══════════════════════════════════════════════════
【赛制设定】
═══════════════════════════════════════════════════

基础参数:
  - 总轮次: 20
  - 号池规模: 288人
  - 代表名额: 6名
  - 赛制: 单循环积分制（本卡改编规则）

运作模式:
  - 始终跟随当前主角模式（一辉模式/OC模式）
  - 不向 AI 开放玩家篡改胜负的模式开关

═══════════════════════════════════════════════════
【参赛名册】
═══════════════════════════════════════════════════

/场景/选拔赛/名册/<ID>
  ID: 稳定参赛者标识符
  姓名: string
  来源: 正典 | 原创 | 玩家
  参赛状态: 参赛 | 退选 | 取消资格
  入赛轮次?: integer (1-20, 可选)

来源判定:
  - 正典: 原作明确参赛角色
  - 原创: 本局新增 NPC
  - 玩家: 由系统模式和玩家姓名自动确定

入赛轮次:
  - 默认第1轮起参赛
  - 中途入赛需明确登记入赛轮次
  - 只能由终端人工纠错，AI 不可创建或修改
  - 登记入赛轮次不重启赛季

退选/取消资格:
  - 明确更新 参赛状态
  - 不再安排新比赛
  - 已完成比赛积分保留

初始战绩:
  - 旧档可能存在此字段（兼容 T01）
  - AI 不可创建或修改
  - 只能由用户终端手动补录

═══════════════════════════════════════════════════
【比赛记录】
═══════════════════════════════════════════════════

/场景/选拔赛/比赛/<ID>
  ID: 稳定比赛标识符
  轮次: integer (1-20)
  甲方: string (参赛者ID)
  乙方: string (参赛者ID)
  日期: string (YYYY-MM-DD 或空)
  时间: string
  地点: string
  状态: 待定 | 已安排 | 已完成 | 已取消
  胜者?: string (参赛者ID, 仅已完成)
  弃权方?: string (参赛者ID, 可选)
  依据: string (结果说明)

约束规则:
  1. 每轮每人至多一场
  2. 已安排/已完成的同一对手组合不重复
  3. 已完成需有明确 胜者 和 依据
  4. 取消不占对手和积分

AI 提交范围:
  ✓ 可以写:
    - 比赛ID
    - 轮次
    - 甲方/乙方（参赛者ID）
    - 日期/时间/地点
    - 状态
    - 胜者（已完成时）
    - 弃权方（如适用）
    - 依据

  ✗ 禁止写:
    - 甲赛前胜场
    - 乙赛前胜场
    - 初始战绩
    - 积分
    - 排名
    - 程序来源
    - 程序保留ID（__rk_bg_ 开头）

═══════════════════════════════════════════════════
【日期与推演】
═══════════════════════════════════════════════════

日期读取:
  - 从 /场景/时间 读取当前日期
  - S01 固定赛程:
    * 4/22: 开幕
    * 4/23: 一辉首战
    * 4/27-5/6: 停赛
    * 7/8: 终战

程序推演:
  - 仅过去的日期槽生成 NPC 场外结果
  - 当天不自动判胜
  - 场外按正典走势与普通 OC 固定种子推演
  - 玩家本人不自动生成胜负

背景战况:
  - /场景/选拔赛/程序战况 为程序只读摘要
  - AI 不抄回初始战绩或赛前胜场
  - 不将背景投影写入业务数据

═══════════════════════════════════════════════════
【积分计算】—— 程序自动
═══════════════════════════════════════════════════

计分公式:
  - 胜者: 10 + 10 × 对手赛前胜场
  - 败者: 0

赛前胜场:
  - 由程序根据该轮之前的所有已完成比赛计算
  - AI 不读取、不写入此值
  - 轮次不能冒充对手赛前胜场

战绩合并:
  - 真实比赛与程序背景合并后统一计分
  - OC 打赢正典人物时，以本轮扮演事实为准
  - 程序替换该轮背景结果，沿实际胜负重算后续积分
  - 不能为迎合正典把败局改回胜利

旧档处理:
  - 旧档的可信 初始战绩 和未知 赛前胜场 只能由用户终端手动补录
  - 已有值沿用，覆盖轮次不重复计分
  - 同一比赛 ID 纠错后重算战绩积分，不增设第二条补分
  - 取消后扣除其派生结果

  约束: AI 不写入

═══════════════════════════════════════════════════
【更新流程】
═══════════════════════════════════════════════════

每轮检查:
  1. 本轮是否有比赛安排？
     - 有 → 登记或更新比赛记录
     - 无 → 跳过

  2. 本轮是否有比赛结果？
     - 有 → 更新状态为"已完成"，写入胜者和依据
     - 无 → 保持已安排状态

  3. 是否需要更新参赛状态？
     - 有退选/取消资格 → 更新名册
     - 无 → 保持原状态

禁止操作:
  - 不自动判定玩家胜负
  - 不编造未知对手/比分/时间
  - 不写积分/排名
  - 不重复计分同一比赛

纠错流程:
  - 同一比赛 ID: 修正后程序重算积分
  - 取消比赛: 状态改为"已取消"，程序扣除派生结果
  - 不删除比赛记录

═══════════════════════════════════════════════════
【结束与代表选拔】
═══════════════════════════════════════════════════

结束条件:
  - 所有轮次完成
  - 或明确宣布结束

代表选出:
  - 依据实际积分与赛制顺位
  - 原著固定名次和命定败局不覆盖本局结果

数据完整性:
  - 学园圈、日程和赛事页面共读此账本
  - 安排不等于已发生
  - 过期、缺席、未来原著安排不自动视为发生
