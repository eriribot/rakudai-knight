# 落第骑士 MVU v5 优化版说明文档

## 📋 版本信息

- **版本号**: v5 执行优化版
- **发布日期**: 2026-10-08
- **核心改进**: 从防御式堆砌转向流程式引导

## 🎯 核心变更

### 一、三层分离架构

原版问题：规则、数据、历史案例混在一起，2400字全部注入。

v5 解决方案：

```
┌─────────────────────────────────┐
│ 变量更新规则-v5-优化版.txt      │  ← 225行，核心流程 + 铁律
│ - 30秒执行清单（每次必读）      │
│ - 五条铁律（边界约束）          │
│ - 核心字段规范（简版）          │
└─────────────────────────────────┘
           ↓ 引用
┌─────────────────────────────────┐
│ 字段定义表-v5.txt                │  ← 464行，完整字段规范
│ - 所有字段的类型/含义/约束      │
│ - 规则文档引用此表，不重复      │
└─────────────────────────────────┘
           ↓ 条件注入
┌─────────────────────────────────┐
│ 选拔赛T02规范-v5.txt             │  ← 228行，仅赛季时注入
│ - 只在状态=进行中时加载         │
└─────────────────────────────────┘
```

### 二、决策树显式化

原版问题：判断逻辑隐藏在规则描述里，AI 需要自己理解。

v5 解决方案：

```markdown
□ 人际变化？
  对每个互动人物：
  - 有态度或信任变化 → 分别计算好感/支援终值
  - 好感与支援度独立判断，不联动
  - 写变化依据（旧值→新值）
  - 无互动或无变化 → 跳过该人物
```

每个判断点都有：
- **明确条件**："有态度或信任变化"
- **明确动作**："分别计算好感/支援终值"
- **明确跳过条件**："无互动或无变化 → 跳过"

### 三、负向指令压缩

原版问题：47 条"不要/不能/禁止"规则。

v5 解决方案：压缩为 **5 条铁律**

| 铁律编号 | 原版负向指令数量 | v5 正向原则 |
|---------|----------------|-----------|
| 1. 独立计算 | 8条 | 魔力控制/魔力量/体能/好感/支援 五者独立 |
| 2. 防重机制 | 12条 | 同一成果只计一次，读已保存值对比 |
| 3. 事实优先 | 15条 | 只记已发生，不写未来/未知/计算值 |
| 4. 类型严格 | 6条 | boolean 用 true/false，类型不混用 |
| 5. 补丁边界 | 6条 | 纠错可改终值，重试不当新奖励 |

### 四、关键术语单一定义

原版问题：`魔人觉醒`、`支援度` 的规则分散在三个文件。

v5 解决方案：

- **字段定义表-v5.txt**：完整定义所有字段
- **变量更新规则-v5-优化版.txt**：只写执行流程，引用字段表
- **变量输出格式-v5.txt**：只写输出约束，引用字段表

## 🎓 设计理念

### 从"判例汇编"到"流程图"

**旧模式**：每次 AI 出错 → 加一条"不要再犯X"→ prompt 变成 bug 修复日志

**新模式**：逆向工程成决策树 → AI 按流程执行 → 从根源消除错误

### 核心洞察

> AI 不需要知道"为什么不能把重试当新奖励"（人类因果），
> AI 需要知道"第 3 步检查 reply_id，相同就跳过"（可执行指令）。

### 三个原则

1. **简单优先**：能用清单解决的不用长篇
2. **正向表达**：能说"做Y"的不说"不做X"
3. **单一定义**：每个概念只在一处详细定义

## 📈 预期改进

基于提示词工程最佳实践，v5 预期改进：

- **认知负荷**：从"记住 47 条禁令"降至"记住 1 个流程 + 5 条铁律"
- **执行一致性**：决策树消除歧义，每次执行路径一致
- **调试效率**：出错时直接定位是哪个检查项，而非猜测违反了哪条禁令
- **扩展性**：新增字段只需在字段表添加，规则文档无需修改

## 🔍 验证建议

迁移后建议测试以下场景：

1. **日常对话**：普通友善交流，应有 +2~10 好感变化
2. **成长场景**：实际训练应正确计算经验和晋级
3. **重试场景**：重试时应读已保存值，不重复加分
4. **空回复**：无任何变化时应提交 `[]`
5. **选拔赛**：比赛结果应正确记录，不写积分/排名
