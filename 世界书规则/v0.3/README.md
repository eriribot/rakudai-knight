# v0.3 世界书规则作者源

导出文件：[落第骑士英雄谭-v0.3规则.json](导出/落第骑士英雄谭-v0.3规则.json)。当前导出三条持续成立的世界设定，全部蓝灯常驻，完整设置见 [导入说明](导入说明.md)。正文直接叙述世界事实，作者依据与程序说明留在正文标记之外。

| 文件 | 当前用途 | 导出名称 |
|---|---|---|
| 00_世界与数值边界.md | 世界书常驻 | 世界设定 |
| 01_U建档流程.md | 保留旧建档设计，建档以开局页为准，不导出 | — |
| 02_六维参照.md | 保留参照资料，开局页评定请求已内置全文，不导出 | — |

开局页的 `buildAiAssistancePrompt()` 已提供建档要求、六维参照、评级公式和文字复核建议。AI 返回的建议供玩家检查；页面按六维自动计算综合初评，不把文字中的 ±1 建议自动应用为总评级。`buildOpeningMessage()` 再携带人物资料、六维、计算结果和开局要求。世界书不再重复提供这套建档流程。

00/04/05 保留对后续剧情持续适用的设定。人物事实与 `第一卷-世界书整理/人物条目` 并用；后卷人物表仅供作者校准，不能把后续事件写成开局已发生的历史。

名称、启用方式和选入文件在 [条目配置.json](条目配置.json) 维护。LK 编号只用于作者定位，不显示在导出条目名中。构建只提取源文件正文标记之间的文字，不注入标题、来源或本文。

在项目根目录运行 `node scripts/build-worldbook-v03.cjs` 重新导出，附加 `--check` 只读核对产物。开局页的公式与参照仍在 `opening-rating-engine` 中维护；`node scripts/check-opening-rating.cjs --sync-anchors` 仅同步 02 的参照资料，无参数只读检查。

`变量接线契约.md` 含旧评定流程，留作历史资料。当前中文变量结构、InitVar 与更新规则见 [MVU 契约](../MVU/README.md)，独立于本目录的三条世界设定导出。酒馆同步与核对结果记在导入说明中。
