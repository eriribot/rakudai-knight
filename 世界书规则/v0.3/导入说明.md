## 条目设置

三条都选择 **⚙️ @D（聊天内系统消息），插入深度 1**。设置已写进 JSON：

| 条目名称 | 默认状态 | 使用方式 |
|---|---|---|
| 世界设定 | 启用、蓝灯常驻 | 等级与实力的区别、人物关系及当前时期的设定 |
| 魔力 | 启用、蓝灯常驻 | 先天魔力量、消耗与恢复、外源供能和觉醒后的成长 |
| 羁绊与觉醒 | 启用、蓝灯常驻 | S 级羁绊的意志支撑、其他觉醒契机和个人选择 |

**插入深度 1** 决定正文放在提示词中的位置，与触发策略不同。三条均为蓝灯，触发词已清空，不依赖最近消息是否提到魔力或羁绊。扫描深度留空，因为它不参与这三条的关键词触发。触发概率 100%，无延迟、冷却或互斥组；仍受宿主的世界书预算限制。

蓝灯表示该条目在世界书被当前会话使用时常驻，不代表世界书必须挂到全局。手动导入时，在世界书编辑器导入这个 JSON，然后仅关联需要使用它的角色；全局选择保持空。

正文直接说明这个世界如何运作。伐刀者评级、魔力规律和已经确认的羁绊设定都作为实际存在的事实表达；原作出处、作者算法和待定数值留在作者资料中，不混进剧情提示词。

## MVU 名称边界

显示名称使用普通中文，LK 编号留在作者源与配置中供维护。三条仍是玩法设定，暂不加 `[mvu_plot]`、`[mvu_update]` 路由标记。

`[InitVar]落第初始变量` 留给后续真正的初始数据条目。当前变量结构尚未确认，所以这次不创建它，也不把玩法说明改名为 InitVar。变量展示、更新规则、输出格式及 schema 脚本同样留待结构确认后接入。本文件是规则世界书，不代表 MVU 初始化与更新闭环已经完成。

## 建档提示词由开局页提供

当前 [开局页](../../第一卷-世界书整理/开局页面/index.html) 的 `buildAiAssistancePrompt()` 已内置建档要求、六维全文参照、初评公式和复核建议。`generateAiAssistance()` 只回填能力机制、限制与代价、战斗风格和六维，判定理由显示给玩家检查；页面用 `profileRating()` 重新计算综合初评。

页面仍保留“至多调整一级”的文字建议，但不会把建议自动写成总评级；上一版说明中的“取消复核”表述不够准确。最终 `buildOpeningMessage()` 还会携带人物资料、六维、初评结果、简要公式和开局要求。

因此 01/02/03 从导出包移出，原 Markdown 留作作者资料。以后若要在正式剧情中进行能力重评，再为该场景补充相应条目；当前不让开局档案中的“六维”等词额外触发整份建档参照。世界书保留的是开局后仍要遵守的设定，不能用一次独立的建档请求替代它们。

## 维护与核对

在项目根目录运行：

```powershell
node scripts/build-worldbook-v03.cjs --dry-run
node scripts/build-worldbook-v03.cjs
node scripts/build-worldbook-v03.cjs --check
```

导出正文来自 00/04/05 Markdown，名称及启用设置在 `条目配置.json` 维护，JSON 由脚本生成。构建统一换行并去除正文首尾空白，保留其余正文。`--dry-run` 和 `--check` 不写文件；构建仅写上述一个导出文件，不访问酒馆、下载目录或网络。

静态检查覆盖：UID、源 ID 和显示名称唯一，正文标记完整、源标题与 ID 对应、导出正文及配置一致、JSON 可解析，不混入 InitVar 或 MVU 路由标记。控制台输出源文件和导出文件 SHA-256。构建器不执行酒馆操作，实机保存核对另行记录；编辑器保存通过也不等于已经验证实际生成时的提示词注入。
