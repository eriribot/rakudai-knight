本轮只改源代码与离线检查。三份 MVU 提示词、研究设定、世界书导出、下载文件和酒馆均未更新；现有可导入 JSON 仍是旧版。请先改提示词并验证，再统一重建，不能把本轮源码检查当成实机验收。

## 已落实的字段约定

- `系统.作品` 仍是 `rakudai | asterisk`：决定开局、主线目录与对应赛事，不决定人物能拥有哪种能力；模型不能修改它。
- 学战人物可选保存 `玩家.伐刀能力、固有灵装、登记等级、魔人觉醒、六维、成长`。没有这些资料时不创建默认值；获得伐刀能力不等于魔人觉醒。
- 落第人物可选保存 `玩家.学战` 的任意已知顶层项。例如仅有 `学战.武装`，不需要学园ID、校内序列或星辰力。子对象仍须符合原字段结构。
- 学战开局原有完整学籍与能力档案继续保留；两套招式互不覆盖。没有新增第三套装备路径，也不自动换算两种能量。
- 等级沿用现有 schema 的 `GRADES`，含历史 `B+、C+、D+、E+、F+`；本轮未改枚举。实际六维另外允许 `A+、S`。登记不是自动评测，未知登记可为 `null`；校内序列仍是1–72名。
- `综合初评` 仍为落第开局的历史评定，由程序维护；不是获得伐刀能力后必须补的新字段。

准确字段、类型和范围以 `世界书规则/MVU/schema.mjs` 为准。`学战` 这个旧路径现在也能用于保存落第人物的学战来源能力或武装，不代表自动入学。

## if / else 边界

| 内容 | 判断依据 |
|---|---|
| 未建档 | 不推进或自行建档，输出空补丁 |
| 落第 / 学战主线目录、卷号及赛事 | `系统.作品`，这里可以 `if / else` |
| 章节完成条件、一次最多前进一个节点、玩家行动权 | 共用段，不放进其中一个分支再让另一个引用 |
| 伐刀能力与固有灵装 | 人物实际拥有的字段，独立 `if` |
| 学战异能、星辰力、武装 | 各自实际拥有的字段，独立 `if`，有煌武不等于有星辰力或学籍 |
| 伐刀成长 | 已建档，且 `伐刀能力` 与 `六维` 都是对象；有经验提交或旧账才结算，不因选择学战而禁用 |
| 魔力量成长及晋级 | 沿用原魔人觉醒规则；成为伐刀者不自动把 `魔人觉醒` 设为 true |
| 人际、日程、已发生事件 | 共用规则，记录本局事实 |

运行代码的判定函数在 `scripts/rakudai-mvu-structure.mjs`：`resolveMvuWorld`、`hasBlazerAbility`、`hasBlazerGrowth`。EJS 没有自动获得这些模块导出，不能直接调用未注入的函数；模板需用相同的字段条件。

字段说明必须允许本轮首次获得能力时新增完整对象，不能因为上一轮没有该字段，就把合法新增字段的说明永久裁掉。详细能力规则可以按实际模块裁剪，新增字段权限与已拥有能力的叙述分开。
