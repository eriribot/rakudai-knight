# 开局初始化修复 · 2026-11-07

交付模式：源码＋可导入开局正则组件。维护源码已更新，未打包整卡。

## 导入

1. 在目标角色卡的正则设置里，导入 `components/opening-init-repair.regex.json`，选择“区域脚本／当前角色”。
2. 关闭原来的 `[开局] 落第 × 学战 双开局` 页面正则，只启用名称带“初始化修复 20261107”的新版。保留 `[开局-折叠隐藏]` 及其他配套正则。
3. 刷新页面，在新聊天测试；正常时应显示“建档成功并已回读”，再复制正式第一幕请求。

SillyTavern 1.19.0 的导入动作会分配新 ID 并追加脚本，不会按文件 ID 自动覆盖旧项。组件文件仍保留当前安装基线的稳定 ID；请避免同时启用两份开局页面。

## 修了什么

- 原来的无期限 `waitGlobalInitialized('Mvu')` 改为最多 15 秒的有限就绪等待。分别提示框架未启动、当前楼层变量未初始化，以及等待过期。
- 失败后恢复确认和复制按钮，保留草稿，允许再次确认。超时操作不会因依赖迟到而自动写入。
- 建档期间复制按钮禁用，直接调用复制函数也会退出，不再增加操作序号、取消建档。
- 等待起点固定聊天、消息、回复页和正文；等待期间切换上下文会拒绝原操作。
- 就绪时直接读取，不新建等待计时器、不调用 Helper 的全局事件等待。等待时仅检查目标变量槽；最终数据仍由 `Mvu.getMvuData` 读取。
- 最新助手消息按楼层从后向前定位，减少整段聊天和历史变量的克隆。

维护源码：`scripts/rakudai-state-browser.js`、`第一卷-世界书整理/开局页面/index.html`。同步生成共享控制器、双作品页面及其替换文本。

交付组件以当前安装版为基线，只装入本次适配器和复制／提交交互；完整可读源码为本目录的 `opening.component.html`。工作区共享模块里已有的其他能力和成长改动未混入此次组件。`build-component.mjs` 逆向回填本次修改后，校验其余页面字节与安装基线完全相同。JSON 只修改 `scriptName` 与 `replaceString`，其他字段保持原值，保留之前的 EJS 修复。

## 原因与证据边界

已复现的链路是：MVU 未发布 → 建档入口的无期限等待不返回 → 写入尚未开始 → finally 未执行 → 确认按钮一直禁用。反复点击直接返回，没有进入建档队列。等待中复制草稿还会令原操作失效，这是第二个独立缺陷。

本卡启用脚本的监听器检查未发现互相等待的初始化死锁。第 0 楼变量管理器的 `{}` 只证明该回复页变量槽为空；变量管理器能打开不等于 MVU 已启动。

玩家确认同卡换到 TT 能成功建档，支持环境差异这一方向，但不足以确定是哪一个宿主、网络请求或插件出错。人工阻断 MVU bundle 能复现长期等待，不代表已经证明玩家当时就是 CDN 故障。此次修复解决我们代码的无限等待与并发取消，不会代替外部 MVU 脚本完成加载，也不会伪造初始变量。
