## 结论

学战终端已有足够的草稿字段：身份、所属学园、星辰力文字、校内序列、武装类别与资格说明、能力招式、其他技艺、场景与人际。首版不需要制造 HP、MP、等级或经验公式。

正式接入的关键是按作品选择数据契约、主提示词、副校正规则和剧情目录。现役终端对落第的绑定很深；仅替换界面文案或副 API 的可编辑提示词，仍会加入落第成长与七星资格规则，并受到 v4 全量校验阻挡。

## 最小分区：什么共用，什么属于落第

| 分区 | 可以共用的语义 | 当前落第绑定 / 学战处置 |
| --- | --- | --- |
| 系统 | 结构版本、是否已建档、玩家身份模式、删除记录、关系计分收据 | `主角模式` 当前是未选择 / 黑铁一辉 / 自定义角色，不应兼作作品标记 |
| 玩家身份 | 姓名、性别、性格关键词、处事风格、所属、角色简介、战斗风格 | 学战初版沿用男性自定义学生限制；所属由选定学园写入 |
| 技艺 | `其他能力.<名称> = {说明, 条件与代价, 掌握状态}` 的表达可复用 | 不能把所有学战技艺都放进落第的 `伐刀能力` |
| 场景 | 时间、地点、切入说明、阶段、已发生事实、日程 | `当前卷/当前章` 及事件 `卷号/章段` 当前依赖落第目录；学战切入阶段还不是目录节点 |
| 人际 | 关系、态度印象、好感、支援度、联系状态、联系依据、联系方式、变化依据 | 这些是本局接触事实；世界书人物库不是已认识名册 |
| 落第能力 | 固有灵装、伐刀能力、六维、综合初评、登记等级、魔人觉醒、成长经验/收据 | 学战默认不显示、不推断、不结算；若以后跨界，必须另有玩家明确确认的映射 |
| 落第赛事 | 场景.选拔赛、场景.七星剑斗祭、破军20轮6席、2013赛历及自动战绩 | 不直接改名为星武祭；首版学战保留普通日程/事件即可 |

人际“共用”指本卡已经存在的一套关系计分方式可继续使用，不是《学战》官方数值设定。现役规则亦明确分数阶段不能倒补告白、婚约或亲密经历（变量更新规则.txt:34–36）。

## 单一作品标记的用途

建议只增加一个概念：`系统.作品 = rakudai | asterisk`，由建档程序决定，用于选择初始化、字段检查、UI、提示词与剧情目录。具体字段名待确认；这不是现有 v4 可立即写入的路径。草稿 `world_id` 已承担同一选择，正式建档时只需映射到一个持久标记。

不要同时引入“世界、宇宙、规则集、世界线、作品模式”等重复开关，也不从姓名、校名或某个能力词猜作品。作品标记不是人物出生地，不说明两个作品已融合，不自动改写旧人物、背景或能力。

`系统.主角模式` 仍回答“扮演谁”；学战开局的 `入学报到 / 学园日常 / 决斗准备 / 星武祭前夕 / 自定义场景` 只是本次切入阶段。将来真的支持原著卷章、自由剧情或交叉剧情时，再定义一个有实际读取者的剧情线字段。现有 `场景.路线=A/B` 已用于落第第10卷分线，不能借来代表作品（schema.mjs:276；scripts/rakudai-story-catalog.mjs:41）。

兼容默认值应只用于“已通过旧 v4 检查且缺作品标记”的已知落第存档；不能把任意未知状态静默判断成落第。旧档保持原值，新学战局使用学战初始化，不用空模板覆盖旧局。

## 学战首版字段建议

下表的持久路径只是讨论用映射。`玩家.学战` 作为一组专用字段即可，不要求本轮迁移落第已有字段或引入通用多世界引擎。

| 现有草稿 | 建议语义 / 路径 | 类型与事实边界 | 写入者 |
| --- | --- | --- | --- |
| `world_id` | 系统.作品 | 枚举；学战为 asterisk | 建档程序；模型只读 |
| `school_id`、`profile.school` | 玩家.学战.学园ID + 玩家.所属 | 稳定学园ID用于校徽/选项，名称用于展示；由同一选定值派生，不让两个字段独立漂移 | 开局选择，之后只随确认转校等事实修改 |
| `profile.name/personality/conduct/desc/style` | 现有姓名 / 性格关键词 / 处事风格 / 角色简介 / 战斗风格 | 文字；空缺如实留空 | 玩家确认后建档；后续主副按事实纠错 |
| `profile.category` | 玩家.学战.能力身份 | 沿用现草稿星脉世代（无魔术师异能）/ 魔术师 / 自定义（见能力说明）；不是落第能力系别 | 开局确认；后续有事实才改 |
| `asterisk.prana` | 玩家.学战.星辰力 | 文字，当前草稿上限1200；描述运用、控制、持续性及负担；不造储量、等级或换算公式 | 主副同一业务权限 |
| `asterisk.rank_status` | 玩家.学战.序列状态 | unknown / unranked / ranked；建议保留三态，未知不能默认为未上榜 | 确认的开局设定或后续真实序列变化 |
| `asterisk.rank` | 玩家.学战.校内序列 | ranked 时为1–72整数，其余必须null；学院内名次，不等于跨校战力 | 同上；不得由星辰力、技能数或关系分推算 |
| `asterisk.weapon_type` | 玩家.学战.武装类别 | undecided / conventional / lux / orga / research / none，沿用现有表单枚举 | 开局选择锁定；后续明确获得/更换才改 |
| `profile.device` | 玩家.学战.武装名称 | 文字；不再写入“固有灵装” | 根据实际持有事实 |
| `asterisk.weapon_notes` | 玩家.学战.武装使用条件 | 文字，当前上限1200；适合情况、资格、已知限制；未知保留未知 | 根据资格或验证事实，不凭类别自动授予 |
| `profile.ability/limits` | 玩家.学战.能力机制 / 共通限制 | 文字分别说明个人异能、星辰力运用、武装功能，避免当作同一能力 | 主副按事实修正 |
| `profile.nobleArt` | 玩家.学战.招式 | 复用 SkillObj 形状，名称是稳定键；nobleArt 只是旧页面内部兼容字段名 | 开局确认；后来学习/改良按事实，建议不等于掌握 |
| `profile.otherAbilities` | 玩家.其他能力 | 复用 SkillObj；武术、技术、生活技艺 | 同上 |
| `scene` | 场景时间 / 地点 / 切入说明；学战切入阶段另行定名 | 相对时间可以保留；不硬造年份，不套用落第2013 | 开局确认与后续真实变化 |
| `context` | 当前身体 / 当前能力边界 / 本局映射的创作约束 | 首版可作为确认后的开局上下文，不必再拆大量持久数字字段；需随剧情演化时再明确字段所有权 | 玩家确认；不得自动采用研究中的融合构想 |

来源：asterisk-mode.js:5–16、25–36、178–204；asterisk-prompts.js:38–50、71–85。

特别约束：

- 排名的“始页十二人 / 在名祭祀书”由状态和1–72名次派生显示即可，不另存真假开关；设置第8位不会自动创建夺位战、胜场或原作人物退位记录（asterisk-mode.js:20–23、239；asterisk-prompts.js:6）。
- `none` 不生成武装，`undecided` 不替玩家确定类别或授予装备；`orga` 也不表示资格已获批或适合率100%。先用 `weapon_notes` 表达资格，不制造百分比阈值或新的审批状态机（asterisk-prompts.js:7、76）。
- 不新增 HP / MP / AP / SP、等级、战力总分或经验数字。落第现规则本来也禁止统一HP/MP等自造消耗（变量更新规则.txt:12）；学战明确不生成A–F、S、六维或魔人判定（asterisk-prompts.js:8、76）。
- `武装名称`、`能力身份`、`序列` 属于不同事实，不能互相推断。暂时疲劳、损伤与负担先记录于文字事实，不自动扣数字槽。

## 人物库保留与本局人际

建议保留现有人物世界书作为可检索资料库，不因进入学战删掉落第人物，也不把全库批量复制进 `人际`。初始 `人际:{}` 与现役初始化一致；本局识别、明确背景关系或实际双向接触发生后，再记录人物关系。

现规则已区分“仅识别 / 已建立联系”，且“已加联系方式”是另一件事。名单、传闻、档案存在、同校或角色出现在世界书中都不等于已经见过；已确认的亲属、师生等背景关系也不能因零分被抹成陌生人（变量更新规则.txt:32–36）。

实际通讯读取者已有守门：lime-story.js:75–86 只选择当前人际内、`已加联系方式===true` 且未删除的近期联系人；:124–129 明确不强迫来信、不补未来、不倒补亲密关系。lime-worldbook.js:44–70 只读取当前 primary 世界书中明确姓名匹配、启用的条目。作品标记未来用于选择适当资料范围，不能代替这些本局接触条件。

现 `人际.<姓名>.已知资料` 只允许身份、登记等级、灵装、已知能力（schema.mjs:243）。学战不能直接写新增“校内序列”“武装”键并期待现役校验通过，也不应为了通过校验把学战武装谎称灵装。正式接入时才讨论小幅增加中性资料字段；原有落第字段与旧值保留。

## 适合先讨论的三个决策

1. **作品开关：** 采用一个作品标记，学战首版以所选学院的自由切入开局；主角模式仍表示身份，正式原著/交叉剧情线等实际需要时再加。推荐如此，避免用多组开关表达同一件事。
2. **能力与序列：** 使用星辰力文字 + 三态序列 + 校内1–72名，不引入学战经验/等级系统。推荐保留 unknown，因“尚未知是否上榜”和“明确未上榜”不是同一事实。
3. **武装与人物：** 武装类别、名称、资格说明分开；资格未知就写未知。人物世界书全部保留为资料库，初始不自动建立熟识关系、联系方式或登场安排。推荐首版沿用现有接触门槛，不增加人物入场状态机。

## 可观察的后续验收信号

确认契约后的首个验收：用一个未上榜、星辰力文字说明、武装待定的学战新局，终端只显示这些实际资料；主请求与副校正请求中没有落第六维/成长/魔人/七星规则，未接触的人物没有自动进入关系或通讯。随后再验新局、连续回复、编辑、swipe、切聊天与重载的同一楼层真值一致性。
