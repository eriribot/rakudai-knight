# 双作校历统一展示 · 2026-11-13

## 交付范围

按用户确认：两种终端均可浏览主世界书里的两作剧情与校历，不按本局作品隐藏；档案继续展示当前存档，章节切换和实际注入继续限定本局作品。

交付模式为 `component`：维护源码与一个可导入终端脚本。不重新打整卡，不改实际酒馆数据。本轮没有搭建临时浏览器、服务或测试目录，检查均使用仓库现有脚本。

## 查到的原因

- 宿主的 `embeddedPhoneHtml()` 按 MVU 的本局作品选择业务页面；外观设置只负责样式。
- 原黑白终端的校历会读取当前角色主世界书；原六花终端的校历只有 MVU 日程、事件、章节控制和注入预览。
- 原 `makeBridge()` 的学战分支把 `worldbookCalendar.read()` 接成了返回空数组的占位实现，未接入实际世界书读取。因此两套终端的校历内容确实不一致。
- 原黑白日历读取器本身没有按作品过滤 `[剧情]` 条目。这次修正的是另一条展示分支没有接通的问题，并非解除注入限制。

截图只有玩家文字反馈，没有当时的存档、页面或日志，不能据此确认玩家的作品值是否选错，也不能把该条反馈直接归因于网络。本记录确认的是上述源码差异。

## 改动

1. 从黑白终端提取现有月历、日期解析、日程展示和原文弹窗为 `terminal-calendar.js` / `terminal-calendar.css`，两套界面共用，不另写第二份日历算法。
2. 两作宿主均连接同一个只读 `readCalendarWorldbook()`。展示主世界书全部 `[剧情]` 条目，不按本局作品或注入可用状态隐藏。
3. 增加折叠的“全部剧情”目录，可直接查阅不同月份及不同作品的原文。浏览不建立本局事件，也不启动注入。
4. 六花校历增加同一套月份翻页、定位剧情、日期标记与原文弹窗；保留本局日程、已发生事件、章节控制和注入预览。
5. 日期定位保持当前场景日期优先，其次已登记日程，再其次世界书明确日期；不固定定位学战第一章，也不拿手机日期冒充剧情时间。
6. 沿用已有读取缓存、刷新入口和跨聊天失效机制。世界书正文留在阅读数据中，不塞进页面目录；目录仅渲染标题和日期。
7. 为六花外观和黑白外观适配共用校历的颜色、容器及弹窗。档案、赛事和主线所属作品的业务路由保持原有语义。

主要源码位于 `scripts/黑白ADV轮盘终端/`：`main.js`、`terminal-calendar.js`、`terminal-calendar.css`、`terminal-app.*`、`terminal-theme.css`、`terminal-asterisk.*`、`bundle.mjs`、`build-asterisk-app.mjs`。

## 注入边界

- 世界书阅读没有写入能力，不会把其他作品的章节设为当前章。
- 学战章节操作仍经 `assertAsteriskStoryWritable()` 及章节正文可用性检查。
- 注入器仍按保存的作品选择目录和 order 范围；切换作品会使旧注入准备失效，缺失或不合格条目仍不能用于注入。
- 本轮未修改剧情注入器源码或重新发一个注入器；上一轮全卷目录版本继续使用。
