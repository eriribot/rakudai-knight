# 学战剧情控制与双语气泡修复

交付方式：源码 + 独立组件。基线为本机 `落第x学战v0.02`，不重打整卡，不修改正式酒馆的卡、聊天、世界书或预设。

## 原因与证据

1. **学战剧情通道已经接通。** 实卡脚本可从绑定世界书读取 order 200–207；隔离的真实 ST 1.19.0 / 酒馆助手 4.12.0 中，原版第五章预览命中 order 205。通过真实宿主事件总线回放发送前生命周期，待发送消息只出现一个剧情块，并通过末端复核。没有向模型发请求，因此这不是模型实际接收或遵循剧情的证明。
2. **终端操作缺口属实。** 六花首页原来没有明确剧情入口，注入开关藏在校历中；学战也没有黑白终端的手动章节操作。现已补首页入口、章节开始/结束/下一章、确认向前切入。既有 MVU 事务继续校验聊天、swipe、状态、生成中与旧凭据；学战的当前卷保持 `null`。
3. **缺失章节会打断后续注入。** 当前世界书没有 `[剧情]` order 208。旧注入器仍建议从第七章进入终章。现在目录标为不可用；第七章原文仍可注入，完成后只结束本章，不自动跳到缺失终章。目录和相邻章可用性共用一次取书，发送前也复核下一章变化。
4. **这次气泡故障来自匿名对白。** 对应原始消息第 2 楼有双语段落，但没有姓名冒号对白；三条气泡正则与源码一致、顺序正确。原消息在实际 ST 正则引擎中复放为 0 个气泡，补一行明确姓名即变为 1。当前双语预设示例使用匿名中文引号，与气泡合同要求不一致。已补双语格式合同；正则和 CSS 不变。

## 导入

在酒馆助手的**角色脚本库**导入：

- [双作品终端](components/asterisk-story-terminal.script.json)
- [剧情注入器](components/world-story-injector.script.json)

酒馆助手 4.12 的原生导入会产生新 ID，并默认关闭新脚本。导入后关闭旧的“黑白 ADV 轮盘终端”和旧的“卷章剧情注入器”，再开启上述两条新脚本；每类只运行一条。其他脚本保持现状。

将 [聊天气泡规则文本](worldbook-uid43-聊天气泡规则.txt) 的全文替换到绑定世界书的“聊天气泡规则”条目的**内容**字段。本机该条目 uid 为 43；其他副本请同时核对名字，不要仅凭数字覆盖。保留条目的原触发设置与顺序。

从终端总览点击“打开剧情控制”，或从轮盘“校历”进入“剧情与校历”。选择目标、填写时间地点和切入说明后，再确认切入。

双语对白格式示例：

```text
☆‹「こちらへどうぞ」›
克劳蒂雅:「请往这边走。」
```

新合同不能保证模型每轮遵循。若自己的双语预设仍持续输出匿名译文，可在预设副本中同步调整该示例；未代改原预设。已有匿名对白不会自动猜出身份，需在确认说话人后编辑该行，或重新生成。
