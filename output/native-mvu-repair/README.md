## 已修复的链路

- 原生更新：约束关闭时，在真实 `VARIABLE_UPDATE_STARTED` 事件内将旧 Zod 哨兵或锁定结构替换为原生可用的 schema；保留 `stat_data`、未知业务字段与外部包装，不批量修改历史楼层。动态人物、子对象和数组采用原生补丁更新。
- 主保存：不等待副 API 或可选约束；仍须本轮解析事件、当前回复页渲染及变量回读一致，不能用旧完整存档冒充成功。
- 副校正：主保存后，有约束沿用业务校验；无约束调用真实 `Mvu.parseMessage`。保存继续检查聊天、楼层、swipe、运行模式及并发变量，随后回读。
- 页面事务：建档、切章、名册与赛程依赖控制器自身能力，保留本地字段验证；关闭约束也可使用。
- 诊断：主保存超时显示“MVU 主保存 · 保存未确认”，副请求问题显示“副 API”；人物缺省好感在原生模式显示待核定，不再要求强制启用约束。

N01 不调用模型，也不注册全局 Zod 业务约束。关闭约束后，成长申请、经验晋级、关系结算等自动业务处理不会执行。已失败的旧补丁不会自动重放；不存在的父对象仍须先用 `add` 创建。模型应继续输出最终值。
