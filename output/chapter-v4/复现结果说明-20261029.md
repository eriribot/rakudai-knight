## 为什么 CMD 可能看不到

注入器 console.info 在浏览器 iframe 内执行，不会自动写入启动酒馆的 CMD。项目固定 ST 后端源码会用 console.debug 打印 requestBody 对象；实际发送 body 使用 JSON.stringify(requestBody)，两者显示形式不同。debug 也可能被日志级别关闭，玩家配置未知。

本机 Node v25.6.0 的对象打印复现：102 条测试消息，剧情在末尾；JSON.stringify 包含剧情标记，但默认对象打印在 100 条后省略，标记不可见。结果如下：

```json

  "nodeVersion": "v25.6.0",
  "defaultMaxArrayLength": 100,
  "actualMessageCount": 102,
  "serializedRequestContainsPlot": true,
  "consoleObjectPrintContainsPlot": false,
  "consolePrintTail": "    { role: 'assistant', content: '离线测试消息 96' },\n    { role: 'user', content: '离线测试消息 97' },\n    { role: 'assistant', content: '离线测试消息 98' },\n    { role: 'user', content: '离线测试消息 99' },\n    ... 2 more items\n  ]\n}"
```

这只证明“日志未显示”可能来自截断，不能认定玩家已经发送成功，也不能认定其环境一定发生截断。玩家若提供的是完整、未截断的实际请求体且没有剧情，应继续按真实漏注入定位。
