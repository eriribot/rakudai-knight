# MVU 标签展示与识别修复

> 本目录是 **v1.3.15 时期的历史标签补丁**，不是当前完整安装包，也不包含正文气泡。已经安装较新小手机或约束时，不要用本目录的历史脚本覆盖它们。

玩家原始 `json_patch` 有数据。旧展示正则漏识别 `update_analysis` 与 `json_patch`，但仍匹配整个外层 `UpdateVariable`，因此两个捕获组为空，画面只剩空框。旧规则还会跨相邻变量块捕获，丢掉第一块展示内容。

展示正则现在兼容标准和下划线标签，并把匹配限制在同一完整外层块。纯未知或不完整块保留原文，避免变成空壳。标题沿用维护源中的“本轮变量输出”；旧截图里的“变量已同步”是静态文案，不能验证实际保存。

## 安装

1. 角色正则：用 [variable-display.regex.json](components/regex/variable-display.regex.json) 替换“伐刀者战术终端·变量折叠”。维护源 ID 为 `e0b51684-257a-422a-a9f8-rakudai00001`，旧卡可能为其他 ID；先停用或移除旧的同名显示规则，再保持一份新规则。保留“提示词修剪·清理历史变量”。
2. 小手机：保留已经安装的较新版本。当前维护产物是 [小手机 v1.3.23](../../世界书规则/MVU/落第骑士-小手机-v1.3.23.json)，已经保留标准／下划线 MVU 标签兼容及玩家气泡桥接；本目录的 `phone-v1-3-15.script.json` 仅留作历史记录，不用于覆盖新版。只启用一份手机脚本。
3. 使用约束时，从 [当前 v4 字段约束](../../世界书规则/MVU/落第骑士-MVU-v4字段约束.json) 获取维护产物，不用本目录旧快照覆盖新版。关闭约束的玩家无需为此重新开启它。
4. 重载酒馆后重新显示原始回复，确认分析与完整补丁可见。N01 与开局控制器沿用上一轮安装，本次不自动重放旧漏写补丁。

小手机和可选约束同步接受 `JSONPatch` / `json_patch` 的大小写变体，仍拒绝重复、混配、半截标签及非数组补丁；保存事件、当前楼层与回复页、并发比较和回读要求保持原样。规范输出仍使用 `Analysis` / `JSONPatch`，不从分析文字构造操作。

## 正文气泡没有出现时

正文气泡使用 [独立的三条 v0.6 正则](../../scripts/正文气泡/发布/components/)，不是本目录的“变量折叠”正则。放在当前角色局部正则中，开启“启用本角色正则”，顺序为 **01 姓名与台词 → 02 OC 姓名候选 → 03 共享样式**；旧副本停用，每条只启用一份。导入文件并不保证当前角色已允许执行局部正则。

若使用已验证的 **Izumi 1002**，还需要 [本卡兼容三条](../../scripts/正文气泡/发布/Izumi本卡兼容/components/)，放在原 Izumi 处理之后、气泡之前：**前缀恢复 → 样式保护 → 规划边界 → 气泡 01 → 02 → 03**。原 Izumi 的已知规划模板会留下未闭合标签，阻止后续气泡匹配；这些局部规则针对该已知模板修复，不代表任意版本预设通用。完整安装与显示条件见 [正文气泡说明](../../scripts/正文气泡/README.md)。

2026-10-08 实机确认：现场是咩咩 ver 5.8.1、气泡 v0.5、小手机 v1.3.23。完整推理段内的“校验 `<wlog>` 名单”触发了气泡规则的未闭合日志保护，导致其后整层正文不匹配；双语美化规则未启用，不是本次原因。v0.6 把完整已知驱动块作为整体判断，实际酒馆引擎只读复放为成功层 22 → 22、失败层 0 → 13，聊天数据未变化。证据见 [现场预览](../../scripts/正文气泡/验证记录/现场掉气泡-20261008/live-preview.json)。此前旧版围栏冲突仅是另一项离线复现，不能解释此现场；Izumi 兼容也不用于处理本次咩咩反馈。

随后玩家附图确认“修复了”：黑乃的头像、姓名与对白气泡正常显示，旁白和折叠标题保留。已记录这次玩家侧画面验收；本任务未自动保存浏览器规则。
