## 首版最小方案

建议一个由建档程序维护的 `系统.作品`，值为 `rakudai` 或 `asterisk`。这是拟议字段名。它选择终端、字段校验、更新提示与剧情注入；`系统.主角模式` 继续表示扮演谁。

现有姓名、性别、性格关键词、处事风格、角色简介、普通技艺及人际记录可沿用。学战专有资料放在一组 `玩家.学战` 中，落第旧字段先不搬迁。新学战档案不被要求补齐落第评级，必须由相应 schema 分支支持。

| 学战资料 | 建议表达 | 边界 |
| --- | --- | --- |
| 学园 | 稳定学园 ID，名称由 ID 映射 | 男性玩家开放五校；女校与人物依然存在 |
| 能力身份 | 星脉世代／魔术师／自定义说明 | 不与武装效果混同 |
| 星辰力 | 文字描述控制、运用、持续性与负担 | 未测定保持未知；先不设战力或经验数值 |
| 序列状态 | 未确认／未上榜／在榜 | 未确认不等于未上榜 |
| 校内序列 | 在榜时为 1–72 整数，其余为 null | 前 12 名的标识由名次派生；不据此伪造夺位战 |
| 武装 | 类别、名称、使用条件分别记录 | 未选与不使用分开；纯星武装不自动授予资格 |
| 能力与招式 | 机制、限制；逐项说明／条件与代价／掌握状态 | 开局候选未经确认不能视为已掌握 |
| 场景 | 时间、地点、切入情境、实际事件 | 暂用自由日常；不冒用落第卷章目录 |

## 人物继续存在

两部作品的人物资料保留，只有本局已识别、明确背景关系或实际接触的人才进入相应人际记录。未登场不会被删除，也不会因为资料库有其名字就成为好友或自动获得联系方式。

学战终端的人物卡片和对白是视觉演示，不表示已与这些人物相识。关系计分若沿用落第现有规则，是本卡玩法规则，不是学战原作的官方数值。

## 分流需要一起接的地方

- 剧情注入：读材料前按作品拦截；学战没有材料时不继续注入落第章段。
- 主回复：变量更新规则和字段格式按作品选择。
- 终端副校正：除了规则文本，还要处理代码额外加入的落第成长、七星资格与完整 schema 校验。
- 终端：学生档案、日历、赛事入口及其写入操作使用对应资料。
- 正文气泡：先做各作品视觉；未来绑定真实消息时按人物身份及楼层来源处理，避免全局切换抹掉历史样式。

## 先讨论的三项

1. 星辰力首版是否采用文字档案，暂不设计储量、评级或经验公式？
2. 学园序列是否保留「未确认／未上榜／在榜」三态，武装保持名称、类别、条件分开？
3. 学战原作剧情待作者编写期间，是否先以学园自由日常运行，只记录本局实际事件？
