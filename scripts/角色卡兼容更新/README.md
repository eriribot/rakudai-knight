# 角色卡兼容更新

这个作者端工具让新版沿用升级前的角色名称，避免旧版酒馆助手按名字保存的启用许可失配。新版内容、资源和气泡修复保留，实际版本写入标准字段 `data.character_version`。以后给同一批玩家更新时继续沿用这个身份名，仅更新版本字段和下载文件名。

例如 v0.07 用户升级后，卡片列表仍显示原来的“落第骑士英雄谭v0.07”，实际内容及版本字段已是 0.08。这是兼容身份；不要为了让列表显示新版本而再次改名。

工具完全在本机读写 PNG/JSON，不联网，不进入酒馆或访问聊天存档。先输出计划，再由 `--write` 创建新文件，不覆盖任何输入、历史发布或已有输出。

## 作者制作兼容包

```powershell
node scripts/角色卡兼容更新/compat-update.mjs --old "升级前旧卡.png" --new "新版内容.png" --version "0.08" --out "兼容更新版.png"
# 核对计划，再使用同一组参数加 --write 生成。
```

可以按已有 v0.06/v0.07/v0.08 身份分别生成更新包，玩家仍在原角色内使用 **更多 → 替换/更新**。这样原生酒馆沿用旧文件身份和聊天。作者旧发行包只代表默认开关；需要保留某位玩家的自定义名字或关闭选择时，以其升级前的角色卡导出作为 `--old`，不需要索取聊天文件。

`--new` 的格式决定输出格式；JSON 输入只能输出 JSON，PNG 输入只能输出 PNG。版本号必须明确提供，不能从文件名猜。每个输出附带 `.report.json`，包含输入输出哈希、组件匹配结果和验证边界。

## 迁移范围

- 使用新卡作为内容底稿，只替换 `data.name`、顶层 `name` 和 `data.character_version`，以及确定匹配组件的开关。
- 同 ID 或清单中明确对应的历史 ID 可以迁移。不会按姓名、列表位置或代码相似度猜组件。
- **保留关闭选择，新包的关闭默认值也优先保留。** 旧卡关闭的手机、正则或文件夹不会被更新偷偷开启；v0.08 有意关闭的 MVU 约束也不会因为旧版曾开启而重开。新增组件采用新包默认值并报告。
- 保留新卡实现、组件顺序、世界书、脚本数据和未知字段。旧卡独有的自加组件不会自动并入新卡；报告列出未匹配项。
- PNG 同步处理 `chara` 与 `ccv3`；正文载荷冲突、重复 ID、类型冲突或不明确的开关值会拒绝生成。图片及其他 PNG 块保持新版原字节。

## 能解决的边界

已定位的旧版助手问题来自更新改名：4.8.19/4.10.0 按显示名记许可，4.11.0 起按角色文件身份记许可。保留名字，再在原角色中替换，可以兼顾这两种身份规则。

总启用许可不在 PNG 中。此工具保留已有身份，不会恢复玩家已经撤销的许可，也不强开全部脚本或正则。原生正则的独立渲染冲突、MVU 数据结构升级另行处理。小手机头像/别名存于浏览器、MVU 数值存于聊天楼层，本工具不迁移或重建它们。

发布工具的自动检查和中性源码复现不等于玩家安装现场验收；报告保留这一状态，不假装已经修好所有未知现场。
