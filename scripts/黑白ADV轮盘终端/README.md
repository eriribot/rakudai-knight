## 名册边界

同伴名册、LIME 通讯录及人物联络页按 `resource/knightavatars/manifest.json` 的名字与明确别名显示头像；玩家使用开局页应用到本局的照片。只改变显示，不预填人际、不补充能力资料。自带盾形构图的图片完整显示，没有盾框的来源使用复用盾框呈现；原始来源是否带框和本地尚未收集头像的人物见素材目录的清单与说明。未知人物或图片载入失败保留姓名首字。

图床地址统一填写在清单的 `characters[].imageUrl` 与 `shieldFrame.imageUrl`，只接受 HTTPS 图片直链。留空时构建内联本地图片；填写后构建输出该地址，运行时加载图床图片。有 `displayFile` 的二十三人应上传 `resource/knightavatars/prepared/` 中的完整彩色合成 PNG，包括凛奈的 `prepared/rinna.png`、夏洛特的 `prepared/charlotte.png` 与福小莉的 `prepared/xiaoli.png`；完整合成图不再二次缩放/裁切，仅叠独立盾框适配暗亮主题。当前32个人物加共用盾框，共33个上传文件。凛奈和夏洛特现均配置原图床目录下的同名 URL，两张远端 PNG 返回 HTTP 200，434×580，且 SHA-256 与本地文件完全一致，见[图床核验](../../resource/knightavatars/research/github-pages/rinna-charlotte-verification.json)。福小莉按用户要求沿用已配置的原图床 URL；恢复地址不代表其第18卷新版已上传，远端是否为新版尚未核验。SVG 盾形遮罩仍内联，无须上传。具体示例见 [头像素材说明](../../resource/knightavatars/README.md)；改完清单执行 `node build.js` 和 `node preview.mjs` 更新导入包与预览。

## 数值与状态栏

档案内部使用深蓝、暖白、金黄、青绿的有限色块；外层窗口与轮盘沿用黑白主题。好感和支援各有独立 div 进度条，雷达保留 SVG。B+=5.5，位于 B=5 与 A=6 之间；未知等级不当作零，不补虚假的雷达点。六维仍是本卡 R05 坐标，不表示战斗力倍率。

好感为 0–1000，普通首次从 0 累计，既定背景首次核定 70–200，旧分原样续算。正向按对方实际回应：日常友善普通 +2～10；新生轻微好感、认可或防备缓和中度 +11～20；重大事件实质改变信任重度 +21～40。负向普通 −1～5、中度 −6～10、重度 −11～20。以上为叙事建议，不再作为拒绝合法终值的硬门槛；依据记录本轮实际回应。单方礼貌无正向回应不硬加，印象与分数一致；同一成果不重结，旧 null 不追补历史。

主 API 直接提交经验与六维终值，不再写成长申请。魔力控制、体能可成长，魔力量仅在魔人觉醒为 true 时开放；经验使用非负整数，按本轮实际成果与旧进度计算，不重复增加同一成果。关闭字段约束时，模型自行按门槛连续晋级并提交最终评级及余量；需要准确门槛校正时，可另开当前约束。终值不受旧申请的 9999 上限截断，S 档保留余额。旧申请、收据与历史记录保留，不参加新奖励结算。

男女支援度均为 0–320，普通协作 +1～5、中度 +6～10、重度 +10～15；这些增量是协作强度参考，合法终值可按事实修正，同一事件不重复计分。C/B/A/S 阈值是 80/160/240/320，由代码派生字母；S 不自动建立恋爱。旧记录缺支援度时显示“待核定”，玩家先确认起点，不从旧字母倒填数字。

本版只支持男 U，`/玩家/性别` 为固定值“男性”，旧缺字段按男 U 兼容，显式其他值被拒。女性 NPC 另按好感派生恋爱阶段：路人 0、在意 200、暧昧 500、交往 800、生死相随 1000；男性 NPC 满好感仍是信任、友情等实际关系。`/人际/人物名/性别`、`恋爱阶段`、`好感突破依据` 为可选的 NPC 字段，不代表开放玩家性别。`人际: {}` 仍为空，初始化仅在玩家下新增固定性别。具体更新规则见开局与写入责任、13b、14h–14i。

## 数据与刷新

`main.js` 将 `state-reader.js` 的只读结果交给页面的 `terminal-app.js`。使用 Tavern Helper 的 `getChatMessages(id, {role: 'assistant', include_swipes: true})`，明确检查 `message_id`、`swipe_id` 后读取 `swipes_data[swipe_id].stat_data`。状态与来源由同一次读取返回，不使用聊天级或全局变量替代。最新助手页无 MVU 时清空显示、等待该页更新，不借用旧页资料。

档案页标注楼层、当前回复页和总页数；楼层使用酒馆原始编号（从 0 起）。删除尾部楼层后跟随剩余最新助手回复；切换 swipe 跟随所选槽。仅滚动查看旧正文、或编辑历史楼层，不会把独立终端锚定到该历史楼层，也不会回写旧槽。

聊天、swipe、删除、编辑等宿主事件触发重读。展开终端时每秒核对已保存变量，覆盖不会发送 MVU 事件的代码写入；相同数据不重绘，收起或销毁时停止轮询，旧异步结果不能覆盖新请求。不消费 MVU 更新过程中的临时数据。

剧情按钮、名册和赛程使用共享状态控制器，无需先开启 Zod 约束；本地字段校验、楼层与回复页身份检查、并发比较和保存回读仍保留。接口依据为 Tavern Helper 4.8.19 对应的消息与事件声明；固定证据见 `世界书规则/MVU/v3_使用与迁移.md`。当前验证不代替用户酒馆的实机版本与写入验收。

## 报错定位

构建额外生成 `dist/terminal.js`、`dist/terminal.js.map`、`dist/terminal-app.html`。JSON 内也有相同的 sourceURL 和内联 source map；支持源映射的开发者工具可查看 `main.js`、`state-reader.js` 等原文件。页面脚本有独立的 `terminal-app.js` / `terminal-controls.js` 来源名。

若只拿到生成脚本行号，可在本目录运行 `npm run locate -- <生成脚本行号>`，打印对应源文件与上下文。源映射按行定位，列号只提供该映射段的起点。

`blob:806` 可能包含宿主包装的前置行，不应直接当成源文件第 806 行。只有确认前置行数后，才使用 `npm run locate -- 806 --offset <实际前置行数>`；不要固定猜为 14。必须使用与报错版本一致的 JSON 和 dist 文件。
