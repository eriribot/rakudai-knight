## 人际与训练判断

- 日常友善互动得到正向回应，按普通好感 +2～10；新生轻微好感、欣赏、认可或防备缓和，按中度 +11～20；重大事件实质改变信任，按重度 +21～40。史黛菈认可分寸、敌意缓和应按中度，不因仍羞恼或“没有重大事件”只改印象；单方礼貌无正向回应不硬加。支援独立按协作成果判断。
- 完成假想敌引导的身体练习，同时实际练魔力控制时，同一来源事件分别申请体能与魔力控制；惯用练法也可获得基础经验。纯脑内动作不算体能，控制练习不自动增加魔力量，觉醒仍仅看 true/false。
- 副模型把申请装在 `/玩家/成长` 或 `/玩家/成长/申请` 父对象时，终端会展开成具体申请。其他申请与结算收据保留；同名待办可修正，类型和方式不作枚举审批。经验可以直接校正终值，同轴申请不再重复累加；收据仍由程序维护。
- 美化正则没有补丁字数上限，220px 只是滚动区高度；完整三项 JSON 就是模型只输出了三项。显示标题改为“本轮变量输出”，保存是否成功以 MVU 结果为准。

## 成长规则

- 唯一权威为 `/玩家/魔人觉醒` 的 JSON 布尔值。字符串 `"true"`、1、境界文字都不能代替。只在本局明确觉醒时置 true；误记由玩家变量编辑器纠错。
- 普通：魔力控制、体能；觉醒后新增魔力量。觉醒不送等级或经验，不再每轮复核资格。
- 每项成长申请为 1–9999 整数，每目标每条完整助手回复合计最多 9999，所有补丁/修复解析共用额度，同来源同目标不重领。基础训练、纠正训练、重大突破仅区分成果性质，不设固定分段；参照评级门槛与实际成长幅度判断，不以剩余差额封顶，不凑满、不靠风险、时长、拆分或改名加奖。

- 普通好感继续从 0 按实际变化累计，特殊关系初始 70—200 和旧分数保留；本次不重置任何关系。

## 关系计分修复 R10

- 好感总范围 0–1000；正向普通/中度/重度为 +2～10／+11～20／+21～40，负向为 −1～5／−6～10／−11～20。每人每完整回复最多 +40／−20。首次背景好感 70—200 按已确认的关系深度及本次两项依据核定，不匹配特定关系词。

## 副 API 使用

主模型负责日常变量，不依赖副 API 才更新好感与支援。每轮只核对实际相关人物，态度变化影响好感，已落实的帮助、配合与小托付影响支援；有事实就当轮提交，没有变化不凑分。旧分数、每轮上限及防重复结算保持。

打开终端 → 设置 → **副 API · MVU 校正**，填写 OpenAI 兼容地址和密钥，点击 **拉取模型** 后从列表选择，也可手填模型名；拉取和保存配置不要求先填模型，请求校正时才检查。地址支持 `/v1`、完整 `/v1/chat/completions` 或 `/v1/models`；输出上限默认 3000。密钥、端点、模型、自动开关和自定义提示词保存在酒馆所在浏览器的本地存储，重载自动恢复；选填补充说明按聊天隔离。密钥输入留空保留已保存值，“清除密钥”清除本机保存的密钥；密钥不会放入聊天变量或导出脚本。

进入设置即自动读取当前助手回复，可展开 **本轮内容 · 自动读取** 查看正文和本轮事件；无需抄写剧情。请求仅附当前这一轮完整正文、该回复 JSONPatch 提交且已保存的事件结果、当前变量、本轮主回复已提交的人际补丁及选填补充说明，不读取近8条或重放整个事件历史。没有本轮事件记录时仍依据正文核对。展开 **校正提示词 · 内置且可编辑** 可修改内置指令或恢复默认，世界书变量规则及JSON格式自动附加。若此前把旧内置提示词复制成了自定义内容，可点击恢复默认后保存，以使用新版内置判断。

**每轮自动校正并保存** 默认勾选，填好连接并点击 **保存配置** 后，从接下来完成的新回复开始工作：等待本轮 MVU 块完整、解析结束、当前页渲染及实际变量保存回读一致，再自动请求、校验、保存和回读。每个回复页的同一 MVU 块成功核对后不重复处理；原有分数已包含主模型本轮结算，副 API 只补漏纠错，不再发一次奖励。空补丁不写入，临时请求故障有限退避重试，其余失败显示原因和可用的重试入口。收起终端不影响自动处理。

已保存的配置在重载后自动恢复；免认证端点也可保存空密钥。首次升级旧版本仍需保存一次，新版不会读取已经丢失的旧会话内存密钥。打开旧聊天不会自动补跑历史轮次。若 MVU 自身设为额外模型模式且关闭自动更新，主结算事件不会出现；终端会说明仍在等待主 MVU，而不会把旧楼层状态冒充本页。关闭自动开关后保存可停用；“取消”停止本次请求。MVU 未完成的生成残片不自动处理；MVU 已完成后，停止剩余正文或生图不取消有效任务。换聊天、换回复页、修改 MVU 块或实际变量会使旧任务失效。

已有这轮需要立即检查时，点击 **手动校正并预览**；预览只检查JSONPatch，不调用MVU、不改正文。确认后点击 **应用预览补丁**，经守卫保存当前楼层及回复页并回读核对。修改配置、换聊天、换回复页、新主生成、MVU 块或实际变量发生变化会使旧预览失效；其它正文和图片刷新不清除预览。

F01 副 API 依据本轮实际内容修正业务变量。父对象只合并提供的键，数组按最终内容保存；add/replace 自动适配字段存在性，remove 可删除过时能力、人物、事件、日程条目，copy/move/test 会在内存中折算。新对象先组装完整再提交，避免必填字段只收到临时空壳。已有数字按终值校正，可核定旧 null 或缺失分数，无需为通过校验重复填写依据；成长终值与同轴申请不叠加。主副 API 共用业务字段写入权，数字校正不再要求固定强度或额外突破凭据。

无需安装 Story Oracle；只参考其独立端点转发思路，代码由本项目实现。宿主缺少 `ChatCompletionService.processRequest`、MVU 未就绪或缺 G04 / T01 与原兼容标记的约束会显示原因，不切换主 API。模型列表通过宿主独立转发读取，未返回列表时仍可手填模型名。
