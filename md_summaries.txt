# v0.3 · 无原创 U 介入时的原作魔力突破人物核查

> 核查日期：2026-09-05。含第十九卷以前的剧情信息。  
> 目的：为 S 羁绊与成长机制提供人物事实清单。最新澄清：S 是核心机制，但觉醒不止一种方式，不锁定原作配对。用户已批准保留开局前已觉醒的身份。  
> 检索范围：本地第零至十九卷、短篇；联网以 GA 文库/SB Creative 官方页面交叉确认。以下是本次取得明确证据的对象，不宣称所有未列人物均不可能觉醒。

## 1. “突破魔力上限”在这里是什么意思

本清单主要收录明确成为魔人、越过先天上限限制的人。第十卷 L1327—1347解释：觉醒者可以通过训练提高魔力上限。它不等于每个人的当前 MP 都已测出具体增量，更不等于立即增加到 10000。

其中一辉有特别直接的证据：第九卷 L5419—5421明确出现魔力最大值提升，第十卷 L1343—1347说明此后可以训练提高上限。

下列情况另列，不能直接并入：

- 吸收外部电力/风等能量，获得额外可用能量；
- 单次爆发、变身或超度觉醒期间的临时变化；
- 升为 A 级、体能成长或开发新招；
- 被前期人物误称为魔人、后期真相推翻的对象。

“没有 U 影响”指原作本来就有这些事件；并不意味着这些人物都在第一卷开场时已经觉醒。

### 黑乃时间线的修正

第十四卷 L72—110回顾的是她年轻时的选择：宁音跨过门，黑乃为了与琢海成婚的未来止步。到第十八卷，她得到家人的支持，才真正踏入觉醒。

因此，“黑乃曾因家庭放弃觉醒”和“黑乃后来因家人的支持觉醒”同时成立。只看前半段，会错误地把她永久排除在魔人名单外。不同卷的丈夫译名为“琢海／拓海”，按同一人物处理。

# 《落第骑士英雄谭》TRPG 战斗与普通多楼层 MVU 世界书设计方案

> 修订：2026-09-05 · v0.2，原作核实与实现评审版。  
> 结论：可以用 MVU 非同层卡实现，但原稿混入了错误设定和未闭合的结算流程，不能直接作为规则或脚本投入使用。  
> 本版交付的是设计与数值草案，尚未实现或验证酒馆运行时。原稿备份见 [修订前方案](output/design-review/TRPG方案-修订前-2026-09-05.md)。

> **评审状态更正**：v0.2 包含未经用户确认的玩法替换，不代表已批准设计。“非官方”只能限制事实归属，不能据此删除本卡自定规则。后续按 [v0.3 讨论稿](落第骑士英雄谭_TRPG战斗与世界书设计方案_v0.3讨论稿.md) 逐项确认；本版的数值、玩法和首版范围建议均需重新区分确认状态。

## 1. 这套游戏要保留什么

核心体验是：**观察对手 → 选择招式与站位 → 承担资源和受伤后果 → 利用已发现的弱点改变战局。**

保留固定招式构筑、魔力天赋差距、剑技与情报的价值、角色关系对协作的影响。采用统一裁决器，让一辉、原创 U 和其他 NPC 都遵守同一套命中、消耗、伤势与胜负规则，角色差异由具体能力体现。

游戏设计依据是「核心循环」「主题一致性」「先做原型再调参」：先证明一场对决有多种有效选择，再扩展招式数量。不要用无条件锁血和无条件秒杀替代“以技取胜”，也不要让每个人定期升级成同一种空间斩使用者。

### 1.1 已确定的产品边界

- 使用正常的用户楼与 AI 楼，每个有效 AI 回复保存该分支的 MVU 状态快照；不改成同层虚拟消息系统。
- 自定义 U 是独立新角色，一辉仍是 NPC。室友、亲属、史黛菈与一辉的感情关系不转移给 U。
- 当前第一卷资料库是基础内容包。第二卷技能、魔人与后期情报单独标记来源和启用条件，不能因研究时读过后卷就注入开局。
- 当前开局页继续保留性格关键词、处事风格；不恢复性别、罗马音和自定义综合等级输入。
- 开局页的 JSON、PNG、本机槽位是建档草稿；它们不等于游戏存档。当前页面仍是生成/复制开局消息，尚无自动发送或 MVU 初始化。
- 第一版只做有限招式的一对一战斗、简单训练、人物关系。多人战、原创概念能力自动裁决、魔人完整战斗系统放到后续模块。

## 2. 先核实原作，再决定哪些规则可以自制

证据分为四类：

| 标记 | 含义 | 使用边界 |
|---|---|---|
| O：官方公开 | 本次联网查到的出版社、动画官网页面 | 只支持页面实际写出的内容；动画资料不能包办后卷设定 |
| L：本地原文 | 用户提供的小说 TXT，按 GB18030 解码后的行号 | 可用于项目考据；与在线官方原版核验分开记录 |
| H：自定规则 | 为文字游戏设计的数值、阈值、行动经济 | 必须明确标注，不冒充官方战力表 |
| U：待核实 | 缺少足够出处，或仅能推测 | 留空、禁用对应扩展，不能由 AI 自动补成事实 |

### 2.1 联网官方确认

动画[官方术语表](https://ittoshura.com/glossary/index.html)确认：评级为 A—F且不含剑术、体术技巧；修罗是限时强化，罗刹是压缩为一击；风之爪痕作用于空间，天衣无缝另属剑术；幻想形态削体力，实像形态有真实伤害。这里没有“魔人统一 S 级”“看破后防御归零”的规则。

[GA 文库角色页](https://ga.sbcr.jp/sp/cavalry/chara.html)列出一辉 F、史黛菈 A、珠雫 B、绚濑 D、刀华 B，并明确一辉剑术实战强。这支持“登记评级与实战表现分开”，不支持用字母直接计算胜率。

魔人方面，[第 12 卷简介](https://ga.sbcr.jp/product/9784797391985/)描述越限挑战与试炼，[第 13 卷简介](https://ga.sbcr.jp/product/9784797393170/)将史黛菈的觉醒与激战、确立自我联系起来；[官方编辑介绍](https://ga.sbcr.jp/bunko_blog/010131/20170809/)还提到爱德怀斯处的修行。公开资料没有提供“先达恋爱 S，再必然觉醒”的通用条件。

[第 2 卷官方简介](https://ga.sbcr.jp/product/9784797375480/)可以确认藏人是前大会八强；它不能证明藏人是一辉不用修罗时的永久战力上限。

本次未在可访问的官方网页中核实完整六轴计算方法、魔力数值换算、十岁检测规则或魔人统一数值表。[出版社第一卷页面](https://www.sbcr.jp/product/4797374681/)有试读入口，但转链本次抓取失败；下列精确比例使用本地文本证据，不冒称已联网确认。

# 《落第骑士英雄谭》TRPG 与 MVU 设计 · v0.3 讨论稿

> 状态：逐项讨论中，尚未整体批准。

## 1. 本版纠正的评审方式

用户指出，恋爱 S 等内容本来就是自定机制。v0.2 将部分“不是官方定律”的内容直接删除或替换，超出了设定考据所能决定的范围。

本版分别处理：

| 类型 | 处理方式 |
|---|---|
| 原作事实 | 核对人物、术语、事件及来源，纠正引用错误 |
| 本卡自定玩法 | 保留设计意图；即使与原作不同，也只需明确改编范围，不能仅因非官方而删除 |
| 数值与体验 | 列出实际收益、代价、适用场景与取舍，交给用户逐项决定 |
| 工程约束 | 明确重复结算、状态写回、事件时序等可复现问题，提出不改变已批准玩法的实现办法 |

v0.2 的考据、算例和技术分析作为参考资料继续保存；其中替换玩法、压低成长倍率、限制招式等建议，不视作用户已经批准。

## 2. 已有明确方向

- 采用普通多楼层 MVU，用户楼与 AI 楼正常存在。
- 自定义 U 作为独立角色加入，一辉仍作为 NPC；原作关系不自动转移。
- S 羁绊是本卡的核心机制，可以提供突破所需的意志支撑；“核心”不等于世界中只有这一种觉醒动力。用户已明确指出，觉醒方式不止一种。
- 不锁定一辉—史黛菈配对：即使两人没有建立恋爱，或原创 U 与史黛菈达成 S，一辉仍可发展其他觉醒契机。其他路线的具体剧情条件另行设计。
- 第一卷开局前已觉醒的人物保留原有身份，按历史事实处理；开局后的新突破逐人讨论，不把原著未来事件直接当成本局必然事件。
- 好感等数字倾向交给酒馆助手脚本控制；具体评分和状态转换仍逐项讨论。
- 本轮不批准全部数值，不自动恢复或采纳任何整套战斗引擎。

## 3. R-01：恋爱 S 如何约束觉醒

### 3.1 保留原稿的意图

原稿“引入火纹式支援”属于有意识的玩法设计。其觉醒事件已有三项条件：S 级关系、宿命绝境、守护对方的意志。不能将它概括为“好感满就觉醒”，也不能在考据时顺手删除。

用户随后明确选择“唯一核心”，并要求先找出原作中没有 U 影响就会突破魔力上限的人物。具体好感分数、S 奖励、濒死保护次数、觉醒收益仍另列议题。

R-02 已确认。用户选择：“保留开局前已觉醒的身份，未来突破逐人讨论（推荐）”。

### 3.6 R-04：不觉醒能否增长魔力，珠雫为何升 A

#### 原作核查结论

| 项目 | 未成为魔人时的情况 | 证据 |
|---|---|---|
| 原生魔力总量/先天上限 | 没有找到可通过通常成长和训练永久扩大的反例；后期仍明确这一限制 | 第一卷 L945—955；十卷 L1327—1347；十八卷 L1839—1843 |
| 当前可用魔力 | 可通过休息回复；回复是补回当前量，不等于扩大原生上限 | 六卷 L5113；七卷 L5237 |
| 原先不能调用的余力 | 可通过修罗等特定机制调用，不是新生成魔力 | 第一卷 L1137—1165 |
| 瞬间输出、控制、转换效率 | 可以训练或改良；不能把它们自动折算成原生上限增长 | 十卷 L5658—5690；十九卷 L2449—2455 |
| 外源“模拟魔力” | 自然干涉系可以吸收自身属性的外部力量，增加当场可动用能量；刀华吸电、王马吞风是直接案例 | 十八卷 L1845—1853；十九卷 L1718—1724 |
| 觉醒后的原生上限 | 可以通过训练继续提高 | 十卷 L1347、L1457 |

因此不使用“没觉醒就完全不能增加魔力”的笼统规则。应分清原生上限、当前储量、输出与外源供能。原作未在所引段落规定模拟魔力的储存期限、离开能源后是否衰减，不能自行补成官方充电规则；训练是否能提高自然回复速度也未取得明确证据。

### 2. ⚠️ 終端打開時隱藏輪盤入口球（需要補充修改）

**當前狀態**: 輪盤展開時入口球會隱藏（`#rk-orb[aria-expanded="true"]`），但終端窗口打開後入口球仍然顯示。

```javascript
async function show() {
  if (SS.destroyed || SS.visible) return;
  if (!SS.booted) await mount();
  SS.visible = true;
  SS.host.classList.add('on');
  
  // 新增：終端打開時隱藏入口球
  if (SS.orb) SS.orb.classList.add('terminal-open');
  
  closeWheel(false);
  // ...後續代碼
}
```

在 `hide()` 函數中添加對應的移除邏輯（約在第 300 行附近）:

```javascript
function hide() {
  if (!SS.visible || SS.destroyed) return;
  SS.visible = false;
  SS.host.classList.remove('on');
  
  // 新增：終端關閉時恢復入口球顯示
  if (SS.orb) SS.orb.classList.remove('terminal-open');
}
```

在 CSS 中添加對應的樣式規則（已存在的 `#rk-orb` 部分）:

```css
#rk-orb[aria-expanded="true"],
#rk-orb.terminal-open {
  visibility:hidden;
```

## 📝 開發註記

### 架構說明
- **破軍微光懸浮球** (`#rk-orb`): 可拖動的入口按鈕
- **終端主窗口** (`#rk-shell`): 包含 iframe 的浮動窗口
- **操作輪盤** (`#rk-wheel`): 8扇區圓形啟動器，對應 8 個應用
- **輪盤遮罩** (`#rk-wheel-curtain`): 半透明背景遮罩

### CSS Class 狀態
- `.on`: 元素可見/展開
- `.terminal-open`: 終端窗口已打開
- `[aria-expanded="true"]`: 輪盤已展開
- `.busy`: 正在拖動或調整大小

### 重要函數
- `toggleWheel()`: 切換輪盤顯示狀態
- `show()` / `hide()`: 顯示/隱藏終端窗口
- `openPhoneApp(appId)`: 打開指定應用
- `buildWheel()`: 構建輪盤 SVG 結構
